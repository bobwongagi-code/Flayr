# 离线检查与反馈闭环

适用 Zero/A/B/C 的人工辅助工作流；不接入生产分析、不改标尺/GT、不自动批准或发送。由执行者整理，不让用户重填历史判断。

## 一次反馈怎样成为下一次的改进

在原任务记录一行：`反馈出处；错误/认可做法；适用范围及反例；修到哪里；本次验证；仍未验证`。

1. 核实是事实错误、遗漏、引用/版本错误，还是单次风格偏好；保留原稿和具体改句，不把后来的解释写成已证根因。
2. 确定性问题先修工具并加正反测试。内容判断先补[纠错对照](review-contrasts.json)，写清产品、材料覆盖、认可的表达、错误替代和不适用条件；长期方法才回到对应模式入口。业务规则改变仍需业务确认，不能自动“学”成全品类规定。
3. 用原失败情形与正确保护例回查。程序只验证结构和可计算条件；语义对照由执行者逐项说明保留与取舍，不能以包含某句话或关键词相似宣布通过。已有判例为曝光开发材料，不是独立验收集。
4. 下一笔自然业务保留首次稿、主判断由谁提出、实质修改及实际人分钟；不为验证说明重开 PAPA，不自动扩样或调用。

当前状态只在原任务入口维护；规则文件指向入口，不复制“下一条审核谁”。历史记录注明日期与被取代关系，不删除。HANDOFF 保留结论和链接，不再增加同一案例的另一份流程规范。

## 学习材料的证据绑定

原 `validate_learning_review.py cases.json` 仍只做字段检查，不回写旧材料。新任务有明确引用时，由执行者从现有文件/帧记录整理索引，再运行：

```bash
python3 scripts/validate_learning_review.py /path/to/cases.json \
  --evidence-index /path/to/evidence-index.json
```

索引版本 1；路径相对索引文件所在目录。SHA-256 来自原文件实际字节；不自动更新错误或过期的哈希。下面为格式示意，`<sha256>` 必须换成真实值，不能直接运行：

```json
{
  "schema_version": 1,
  "packet_sha256": "<cases.json sha256>",
  "teaching": {
    "path": "teaching-points.md", "sha256": "<sha256>",
    "points": {"T1": "## T1 使用过程"}
  },
  "videos": {
    "submission-03": {"path": "03.mp4", "sha256": "<sha256>", "duration_seconds": 60}
  },
  "evidence": {
    "E03": {"video": "submission-03", "time_range": [18, 27],
      "frames": [{"path": "03-21s.jpg", "sha256": "<sha256>", "time_seconds": 21}]}
  },
  "cases": {
    "03": {"video": "submission-03", "facts": [["E03"], {"unresolved": "原声尚未听审"}]}
  }
}
```

- `cases` ID 必须与材料包一一对应；每个 `facts` 位置对齐原包的一条事实，不改原事实来适配索引。每项用非空证据 ID 列表，或明确的 `unresolved` 原因，不能留空冒充已核。
- 教学 ID 必须在索引中，引用原文含该 ID 且实际存在于同一教学文件；这只验证文本归属，不证明对教学目的的解读正确。
- 视频、截图按哈希绑定；证据 ID 属于本案例指定视频，时间必须在**索引声明的时长**内，帧时间必须落在证据范围内。时长、截图时间取已有可信 manifest 或核查记录，不从文件名猜。工具不运行 ffprobe，不证明声明与真实视频时间一致，更不证明截图由该视频生成；这些来源责任仍需原提取记录或人工核实。
- 输出列出绑定数量、未闭合事实及包/索引哈希。存在 `unresolved` 时只是其余绑定可检查，不是材料齐全或可发；索引不是对恶意同时改写原件与索引的签名保护。
- 没有结构化索引时明确记“引用绑定未验证”，不要从自由文字猜 ID/时间，也不要求用户重新标注。需要外发的事实仍须实际核查。

## 最终单文件 HTML 的交付预检

```bash
python3 scripts/validate_review_delivery.py /path/to/final.html \
  --author-region directions --author-region shoot
```

填写实际作者阅读区域的 ID，可重复指定；内部资料不用作者词库扫描。不要为了过检选一个无关小块或漏掉正文。输出 JSON 到标准输出，不写原稿、不联网、不运行页面脚本。工具使用现有 Pillow 解码内嵌图片；环境缺少时明确失败，不安装依赖。

检查本机路径（包括内部文字）、资源引用、片段锚点、HTML 结构、内嵌图片字节及所选作者 DOM 文字。单文件只接受内嵌 PNG/JPEG/WebP 和文内跳转；CSS 资源、外部资源、嵌套页面等不在此交付形式内，不能靠放宽检查称可携带。

JSON 记录最终文件和检查器的 SHA-256、作者区域及检查结果。复核已有文件是否仍为原字节，可追加 `--expect-sha256 <上次文件哈希>`；正文、图片或内部区改动均改变最终哈希，需重验。工具不保存/继承人工批准，更新检查器后也应重验。

浏览器实际布局、截图是否支持句子、动态脚本、第二台设备、母语和可转发范围仍分别核查。自动通过不替代这些检查；PDF、音视频也不以旧 Markdown 的 PASS 替代实际成品。不要为静态文档修改运行全量应用测试；只测受影响工具、相关回归与实际产物。

## 四种状态分开记

沿用原任务记录，不建新审批系统：

| 结果 | 需要什么 | 不能代替什么 |
| --- | --- | --- |
| 自动检查 | 命令、最终文件哈希、范围及结果 | 重点、来源真伪或截图语义 |
| 执行者/AI 复核 | 本次实际稿的判断、反证与取舍 | 独立审核或业务认可 |
| 人工确认 | 实际确认人/日期、文件版本、确认范围 | 当地语言通过、已发送或效果已证实，除非明确确认这些 |
| 尚未验证 | 具体缺口及原因 | 不填为零错误、未采用或自动失败 |

后续改动使哪个结论失效，就重查哪个范围；未变且已核的来源继续复用。未知不阻挡无关的本地工作，也不能被温和措辞藏进可发稿。

## 每次交接的最小记录

在原任务入口补充以下信息，不另建表单、审批队列或第二份进度文件；相同记录可引用已有检查输出和确认消息，不重复录入：

```text
当前产物：文件/版本/SHA-256；适用作者、商品与用途
来源：本次核对范围、绑定结果、具体待核项；未检查写未检查
自动检查：命令、检查器版本或哈希、实际产物哈希、范围与结果
执行者复核：谁、何时、复核范围与结论；未做写未做
人工确认：实际确认人/时间、对应版本、确认范围与处置；未确认写未确认
发送：是否获准及范围；实际已发/确认未发/未知，不能用获准代替已发
下一步：剩余事项、下一负责人及反馈时点；已收口则说明本次完成边界
```

没有实测记录就保留未知，不为了填满而猜确认人、工时、日期或发送状态；执行者整理已有信息，只有确实缺业务决定才询问。格式服务于一次现有定稿，不新增逐条人审或让用户重填表。无工具检查的产物明确写不适用或尚未验证及原因，不能编造 PASS。

文件变化后，旧哈希绑定的检查和确认不覆盖新版；修改人标明受影响部分并重查，不要求重审所有未变来源。来源变化导致旧核对包/审核失效，与原任务历史删除是两回事；已发内容由原商务处理必要纠正，不声称代码能撤回文件。旧自动分析的运行、发布与审核权威及联动回归见 [开发维护说明的状态权威一节](../DEVELOPMENT.md)，不强加给 ABC 静态材料。
