# Flayr 升级冻结方案

- 版本：v1.1（内部一致性与执行条件复核）
- 冻结日期：2026-10-18，Asia/Singapore
- 定位：作者内容策划与反馈工具
- 依据：本轮用户确认的升级方向及[ABC 详细需求](flayr-abc-product-requirements-20261015.md)
- 历史：[v1.0 原文](flayr-upgrade-frozen-plan-20261018-v1.0.md)保留；本次只澄清执行与衡量，不改变 ABC、产品分工和首轮业务方向。
- 状态：产品方案冻结。不是代码版本冻结、功能已实现、试点已完成或外发授权；本次不开发、不调用模型、不处理视频、不提交或推送。

## 1. 冻结结论

升级现有 ABC，不增加 D，不合并仓库。Flayr 组合商品理解与带货表达知识，围绕作者对一款商品的持续创作提供帮助，而不是围绕评分组织产品。

商业目标是帮助作者持续产出有购买说服力的内容。直接交付是商品理解、可拍方案、准确反馈与后续方向；首轮验证使用情况、内容质量和团队成本，不承诺成交提升。

能力积累不等于稳定执行：PAPA FEEL、Nor_Wan、Teashell 的既有讨论不能证明自主判断或成稿已稳定。旧评分代码保留，业务主线不展示档位、不以运行自动比较链为前提；本方案不更改实际生产命令、校验、模型路由或 GT。

## 2. Flayr 承担的 ABC

| 方向 | 冻结职责 | 交付与边界 |
| --- | --- | --- |
| A：内容诊断与反馈 | 核对实际表达，结合商品、实际发出的学习材料和整片提出反馈 | 优先明确核对，重点诊断作为待审草稿；不是评分、学习考试或自动验收 |
| B：内容策划与拍摄方案 | 帮助起步拍摄、调整表达及持续创作，形成方向、脚本或镜头方案 | 一页起步包、脚本、拍摄卡、报告页按需选用；不是四条产品线，不默认全部发送 |
| C：共用商品与参考资料 | 复用商品地基，维护商品内容简报、参考判断、反馈和反例 | 内部共用底座，用已有文件和链接，不新建库、不要求任务先入库 |

```text
C：商品内容简报＋参考判断
  → B：准备拍 → A：看实际交稿 → B：下一条方向
  ← 实际任务中的事实纠正、适配反馈和可复用案例
```

这是按需启用的合作过程，不要求每位作者走完。S1-S6 用于理解吸引、引出、讲解/使用、结果、信任及购买引导的作用和承接，不是六段必须齐全、互斥或固定顺序的模板。

## 3. C 的两类资料

| 类别 | 内容与粒度 | 产生、更新和负责人 |
| --- | --- | --- |
| 商品内容简报 | 每款商品一份适用版本：身份/相关 SKU、核心购买理由、表达路径、可选方向、表述来源及边界、参考和待核项 | 内容负责人整理，指定维护人和确认人；未变且用途相同时复用，不要求每位作者重核全部地基 |
| 参考片段与案例 | 每条来源绑定的表达判断一条记录：原片时间、实际做法、表达作用、适用条件及反例 | 从 A/B/ClipMentor 实际工作中积累；每次复用在原任务记用途和反馈，不重复复制案例，不因复用次数自动认定正确 |

简报区分商家主张、已观察、人工确认、分析提议及未知。商家表述是来源，不自动成为效果或合规保证；不要求完整说明书才给普通拍法建议。

商品身份、相关规格/配方、用途或口径变化，或发现事实错误时，由维护人标明受影响条目、复核后升版本；旧版留档，不静默继承确认。新爆款出现先检查是否提供新信息，不自动改变简报。相关未发稿暂停该部分复用，已发内容由原商务与内容负责人处理必要纠正，无关内容不全量失效。

简报确认不是所有派生稿免审：新作者、场景、个人经历、语言、脚本及关键素材变化，检查相应新增内容。当前没有自动依赖追踪、失效传播或按镜头检索，文件级维护不能写成代码门禁已完成。

## 4. 三个产品的职责与互动

| 产品/业务方 | 自己负责 | 交给其他方/接回 |
| --- | --- | --- |
| Rootify Agent/运营 | 经营分析、合作背景、商品身份及标签数据；主动检查发布表现，决定内容请求的分流 | 给 Flayr 作者诉求、商品、视频、同口径经营/推广信息及 A/B 请求；接回可用于报告或沟通的已核内容发现与方案 |
| Flayr | 商品内容理解、参考表达分析、策划、新脚本提议、交稿反馈和证据绑定 | 给 ClipMentor 商品背景、学习目的、参考与候选解释；接回最终实际使用的教学内容，供后续辅审 |
| ClipMentor | 教学选点、讲解组织、心译制作、原片 storyboard 及成片验收 | 返回最终讲解点、原片与教学时间、作品/脚本链接和版本；可独立接任务，不强制先经过 Flayr |
| 原商务/内容负责人 | 商务统一联系与发送；内容负责人确认具体输出 | 在原任务中记录发送、修改、反馈和实际采用，不新增审批队列或要求作者填表 |

Flayr 不替 Rootify 选品、配品、安排作者多拍，不改主库、不自动发送；不替 ClipMentor 剪辑、配音、加字幕或宣告成片通过。半月合作回顾和橱窗报告归 Rootify 原有业务，Flayr 只供应其中需要的内容材料。

原片 storyboard 忠实于参考；Flayr 为作者新设计的脚本明确标为可改编提议，不能冒充原片表达。A 对照实际发给作者的材料版本，而不是后来更新的草稿。

交接先用文件和可读链接，保留作者/商品、本次请求、版本、来源及具体待核项。不建 API、跨库同步、第二套分析器或编辑器。

每笔由原商务作为协调联系人，内容定稿人负责接单、退回缺项或给出可交付版本；在原任务备注记录当前处置、下一位负责人及预计反馈时点，时点结合实际拍摄安排确定，不另造队列。暂不介入也要回给请求方原因和下一观察时点，不能让请求停在交接处。错过拍摄窗口时先确认建议是否仍有用，不把迟到材料算成有效拍前帮助。

内部可读取的作者原片、聊天、商家资料或他人参考，不等于获准转给另一作者。使用前由原商务/内容负责人核本次用途和可转发范围；未获准的参考只留内部，改用获准截图、链接或独立拍法描述，不妨碍不依赖该素材的内容。交接沿用原来源链接，不扩散其他作者的私有信息，不新增一套授权系统。

## 5. 作者在什么时候收到什么

| 时机 | 给什么 | 运行方式 |
| --- | --- | --- |
| 拿品时 | B 轻量起步包：购买理由、可改编方向和脚本；现成心译适合时一起给 | 原商务在已确认合作/发送范围内主动发，不等待新心译 |
| 拍摄中需要示范 | B 脚本配已有真实截图/片段，说明表达目的及可参考拍法 | 作者来要时给，先人工选片，不承诺自动逐镜头检索 |
| 发片前自愿回传 | A 事实核对、待审诊断及具体反馈 | 自愿发来时回应，不主动安排测试、不强制返稿 |
| 发布后 48-72 小时 | Rootify 主动首查后，按情况给 A 反馈、B 新方向或现成心译 | 不等作者求助；有值得交付的结论时原商务主动跟进，不机械发消息 |
| 每半月、每月 | 原有合作回顾/橱窗报告，按需引用 Flayr 内容 | 按既有业务节奏由原商务发，相关内容合并，不重复推送 |

每位作者每款商品在本轮试点/明确的一轮商品合作中，默认主动内容推送 2 次，最多 3 次，不必发满；本轮起止在启动时明确，不自动重置额度。同商品的新增拍法即使放在报告/回顾里另发也计入，合并一次发送只计一次；纯经营回顾沿用 Rootify 业务，不因提到商品就占拍法推送额度。作者主动求助后的必要回复不算主动推送，不借回复追加无关内容。错误材料的必要纠正不能因额度用完而隐瞒或延期，由原商务协调，并保留记录，不夹带新推广。跨商品联系由商务统筹，单商品额度不是密集联系的许可。

## 6. 发布后的主动数据触发

Rootify/运营负责首查与数据状态判断，按同款可比视频及曝光、投流、价格、活动、时间等背景提交请求。无可比对象或缺失推广数据时注明，不把缺失当零投入，不强排内容优劣。首查窗口不是视频统一成熟期，也不代表已有实时自动监控。

启动前核实由谁发现新发布、如何取得更新数据及其截止时间，不能把本地历史累计快照当发布后 48-72 小时数据。届时无新数据，运营仍记录“已检查、数据不可用”，注明已有快照日期、缺项、负责人和下一检查时点；不得标成零订单、低播放或已完成数据分流。A/B 不依赖该数据的明确求助仍可处理，但数据触发环节只能记受阻，不能宣称闭环跑通。等待更新不自动授权新接口或收费取数。

比较优先使用各视频发布后相同龄期的可得数据，保留日期、截止时间、币种/销量单位及商品/SKU 身份；同一统计窗口内视频年龄不同，不能直接当可比。数据只能支持当前业务分流，不计算缺少分母的转化率，也不从成交弱直接定位内容原因。

| 信号 | Rootify 提出的请求 | Flayr 处理 |
| --- | --- | --- |
| 有曝光、成交有限 | 提供观察窗口及可用点击/订单/推广等信息，提出 A、B 或组合需求 | 查相关表达，必要时给改法、新角度或参考；不预设问题在 S3-S6 |
| 开始出单、作者准备继续拍 | 结合数据、合作意愿和资源提出 B 需求 | 保留已有贡献，延展有用的新方向；不自动追加固定数量脚本 |
| 同款多人出单 | 运营判断是否值得扩大合作，并给对象与背景 | 提炼可迁移表达及条件；不自动群发、不承诺跟拍能爆 |
| 播放低或原因不明 | 判断有无具体内容求助，必要时继续观察 | 有依据再分析，不默认开头有问题，不强行给 S1 建议 |

触发可为“A／B／两者结合／暂不介入”，由 Rootify 人工在原任务交文件/链接即可。Flayr 接手后负责内容判断，不把数据状态当内容缺陷；商务负责联系时机和发送。不能用固定 1000 播放、销量名次或经过 48-72 小时直接决定改法。

## 7. 内容、表达和审核的冻结边界

- 从商品购买理由与整片表达出发，不从易截取的局部镜头倒推首要建议。既查事实，也查重点是否被用上，不能只审有没有越界。
- 简报/脚本先说明每段想表达什么，再给具体可改编拍法；不强迫同一画面/顺序/台词，也不退回抽象的“讲清楚”。
- 教学和参考不自动变成必拍要求；明确合作约定单独核准。有动作不代表对象正确或表达到位，真实使用与效果结果分开看。
- 核对区分已定位、未找到、不确定、处理失败；只有相关范围充分核看或明确人工核实，才能确认没拍。不把已拍内容包装成缺失。
- 关于现有视频的事实句绑定真实来源与时间；动作或缺失判断不能靠单张截图证明。拟拍建议另标提议，已有画面不替新品证明效果。
- 作者文字平视、具体、可执行，不出现内部档位/状态，不许诺销量提升，不塞例行审核提醒。内部分析与作者稿分开，沿用[共用表达审核](creator-communication.md)。
- 定稿审核合并到原内容流程，复用已核且未变材料，只复查变化及上下文。代码扫描不替代语义、图文或母语审核；简报确认不能免除具体作者稿定稿。

## 8. 商品标签的位置

Rootify 标签用于同 ID 及相近功能/对象的参考检索，连同标题依据提供用途核查线索。场景覆盖不全、粒度不均，不以缺标签判不适用，不把标题当全部用途的绝对上限。

商品地基和素材分析形成购买问题、场景推理、钩子及结果镜头；视频历史支持重复判断，实际材料或本人确认支持资源判断。这些贡献不归给标签，不从旧画像推测作者有孩子、宠物或车辆。

下一笔 B 内部记标签找到的有用参考或实质改变的建议；没有则记无。持续无帮助时，不把读标签设为 B 必经步骤，保留参考索引用途。不全库补标，不新建标签体系。

## 9. 首轮试点的冻结范围

选择一款已有至少 5 位作者实际拿品、仍有本轮合作及拍摄机会的商品。历史带货人数不能代替拿品名单，5 人不代表统计验证充分，也不是未来所有商品的永久门槛。

固定两份范围但仍放在同一任务记录中：商品候选范围含已核拿品作者及进度；前瞻起步组只含本轮能在拍摄前收到帮助的作者。至少 5 位是商品候选条件，不等于起步组必须满 5 位。已拍完或已发布者可另接 A/B 反馈，但不混入起步组或其采用统计；无法确认阶段则保留未知。若无人还有拍摄机会，就不选该商品，不靠增加历史视频充数。

1. 落实商品、候选与起步组名单、拍摄进度、原商务、内容定稿人、简报维护人、本轮起止与收口日期、总人工投入上限；确认数据更新方式、发送范围及必要调用预算。投入上限由业务负责人按实际资源在启动前填写，不虚构金额或人分钟，不要求作者填表。未落实时可以整理已有资料，但不进入正式发送和统计试点。
2. 整理并确认 C 商品内容简报，保留来源和适用范围；不要求用户先写标准答案。
3. 为名单内各作者准备并定稿 B 轻量起步包，在明确授权内由原商务发送；不愿接受、未准备拍或条件受阻的如实记录，不强发、不悄悄剔除。
4. ClipMentor 有合适现成心译就接入，没有不专门制作；先用已有截图、时间点和脚本，不等待新视频。
5. 自然发布后由 Rootify 在 48-72 小时首查并提出 A/B 分流，Flayr 按需要返回内容，商务在联系上限内跟进；A 发片前反馈仍属自愿入口。
6. 在预定收口日期汇总使用、质量、成本及经营观察，分别报告起步帮助和发布后跟进是否实际发生；没有发布或未取得新数据，只能说明已发生环节的结果，不能称闭环通过。不为凑采用增加对象、改窗口或追加推送。无后续视频或超出窗口的记未观察。

这是计划范围，不代表已选商品、落实人员、取得材料或发送。新增模型调用、采集、制作和外发仍按具体任务授权，不占历史基线/实验预算。

## 10. 怎样记录与决定是否继续

采用情况是首要使用指标，检验作者是否需要帮助；质量是放行条件，成本是继续投入条件。采用不等于表达清楚，更不等于成交提升。

| 记录 | 口径 |
| --- | --- |
| 触达与启动 | 拿品、实际发送、回应、开拍（明确反馈才记）及首发日期；未知不估算，可发不等于已发 |
| 使用 | 锁定前瞻起步组分母，分别报计划参与、实际发出、表示愿意、建议后续出现、可确认采用、表达清楚人数；确认采用人数/固定起步组人数是已确认下界，另报可观察作者中的比例及全部未观察人数 |
| 质量 | 保留首稿和最终稿，记录主判断由工具/执行者提出还是业务方补入、事实错误、主要建议是否被重建、后续表达是否清楚；普通措辞改动另记，不按镜头数量代替质量 |
| 成本 | 共享简报准备与确认、个人适配/审核、沟通、反馈和积累的实际人分钟；共享成本只分摊一次，等待/任务历时另记 |
| 经营 | 播放、订单及推广/价格等原窗口信息，只描述，不自动归因内容 |

没有实测人工基线，不报省时百分比；没有完整核查，不报完整召回率。首轮不以任意采用率阈值宣布产品有效，不借成功个案隐藏未观察或拒绝情况。

采用按“作者、商品、本次实际发出的建议版本、后续视频”关联，明确先发建议还是先拍/先发布。作者原本已在做的拍法标为既有延续；后续出现相似镜头但拍摄先后不明，只记对应表达出现，不当作建议促成的采用。已有视频/草稿、明确拍摄时间或作者反馈能支持关联时，保留依据再记确认采用，仍不证明内容/销量提升由工具造成。

起步包和发布后补发方案分别记录：只收到后续方案才出现的做法，不能计入起步包成绩。一个作者多个视频保留明细，人级覆盖只计一次，不用同一人的多条视频放大人数；要点采用不等于视频完整或必须项全部满足。明确未采用、尚未拍、没有可读视频、数据获取失败分别记录，不把未观察当失败或剔出分母。

达到预定总投入上限时停下记录实际用量，由业务负责人判断继续或收窄，不为完成闭环无限投入。收口可为“本范围内继续人工服务／收窄后另定方案／暂停／证据不足”，并说明需求、质量、成本和数据环节的依据。首轮不以此批准自动化或扩大范围；没有后续材料只能是证据不足，不能通过也不能据此判服务无价值。

首次出现新增流程导致的实质错误反馈，或简报事实被证实有误，暂停受影响内容复用与发送并核查，保留已发生错误；未发前发现也记录并退回，不当质量通过。无需求、主要判断反复需人重建或人工成本不合业务时，先收窄服务，不自动扩样或开发。

反馈沿用原任务一行记录，由商务/运营补观察、内容负责人补表达核对、维护人决定是否更新 C：

```text
日期｜作者/商品｜实际发出版本/时间｜回应或未知｜采用/未采用/未观察及视频时间依据｜事实纠正/参考复用｜复核人｜简报更新及版本
```

## 11. 本轮不做

不新增 D、不合仓、不重排仓库；不开发页面、检索库、自动监控/API、自动发送或跨库写入。不重写评分标准、不改 GT、不删除旧代码、不重跑历史视频。AI 素材生成、自行拍示范、专门制作脚本视频化另记方向，本试点不做。

旧明确要求核对 3+3 笔及 20%门槛仅保留历史范围，不能套到此次起步帮助闭环；历史预算、验收数字不随方案升级自动恢复或转用。
