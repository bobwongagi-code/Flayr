# 首次交稿核对试点：材料与简易记录

日期：2026-10-15。依据：[ABC 需求文档 v0.2](../../flayr-abc-product-requirements-20261015.md)。方案已获用户同意，尚未开始业务试点。

2026-10-18范围说明：本文保留原“明确要求核对”的3+3笔历史方案，不是升级后ABC的当前开工要求，不因职责更新自动启动。当前“商品简报与起步帮助”的建议试点、负责人及量法见[现行需求第7节](../../flayr-abc-product-requirements-20261015.md#7-当前升级版的最小试点方案建议未启动)；两者的样本、授权和门槛不得混用。

本轮只观察和记录，不开发页面、不调用模型、不重跑视频。先做 3 笔现行流程基线，再做 3 笔人工辅助试点。无需一次提供全部材料，也不需要重新填写 S1 至 S6 或 GT。

## 1. 现在提供什么

先确定一位审核人，后面两组尽量由同一人完成。内容负责人可由审核人兼任；辅助组的陪同人员到开始前再确定。

每笔任务只需以下材料，可以直接给本地路径，不必另排版：

| 必需材料 | 最简单的提供方式 |
| --- | --- |
| 首次交来的视频 | 原文件或可读的本地路径；注明作者代号、商品名称 |
| 当时交代的要求 | 原聊天文字／截图、脚本或分镜，给实际发给作者的版本；无须先整理成表 |
| 审核结果 | 正常审核结束后，提供最终反馈原文，注明已发或仅定稿；没有修改意见也照实记录 |
| 过程记录 | 按下方模板记真实用时和异常，不补估过去的时间 |

已有原文、译文或合法 Flayr 产物可一并给路径，但不是前 3 笔基线的必需材料。不要专门生成转写、抽帧或模型分析，也不需要准备爆款对照视频、心译视频或素材库。

如果只有口头约定，审核人先记录回忆中的原要求，注明是否确定已经向作者交代。区分必须项与可改编的参考拍法，不确定的先留空待核，不把事后想到的建议算成作者漏做。整理及澄清时间计入本笔任务。

## 2. 前 3 笔怎么做

1. 依次记录自然到来的真实首次交稿，不挑容易的，也不用已经熟悉的旧案例重复计时。
2. 按平时方式审核，使用日常播放器和已有资料。我不提前筛片段、改写要求或给建议，以免改变基线。
3. 从为这笔审核整理材料开始计时，到反馈可以交付为止。中途做其他事暂停计时，等待时间另记。
4. 结束后把材料、反馈和简短记录交给我整理。没有记录到的时间写“未记录”，该笔不能用于省时计算，不自动另找一笔替换。

如果日常流程必须新增模型调用，先说明这一依赖；本试点不代发调用，也不通过撤掉原有必要步骤伪造一个更慢或更快的基线。

## 3. 每笔只留这张记录

可以直接在聊天里按下面几行回复；不必另外制作 Excel。

```text
任务：基线1／基线2／基线3／辅助1／辅助2／辅助3
审核人：          日期：          是否以前看过这条视频：
开始时间：        可交付时间：    中断或等待：     分钟
实际操作：要求及材料整理 __ 分钟；找片段 __ 分钟；判断 __ 分钟；反馈定稿与复核 __ 分钟
其他人协助：姓名、做了什么、实际用时；没有写“无”
要求：原本书面／口头补写／混合；必须项 __ 条，参考项 __ 条，不确定 __ 条
改编判断：涉及 __ 条，约占上述判断时间 __ 分钟；材料有无帮助：
结果：反馈直接采用／轻改／重写；原文或文件路径：
异常：遗漏必须项／错片段／译文误导／其他实质错误／无；是否在发出前发现：
```

改编判断用时是“判断”中的子项，不再加一次；口头补写归入“要求及材料整理”。候选整理、命令行文件准备、素材入库都要记时间，不能藏到陪同人员工作里。有重叠或未计时的子项如实注明，不编数字凑总数。

辅助组另加一行，由陪同人员填写，审核人不维护技术表：

```text
候选：提供人 __；提供 __ 段，核对相关 __ 段，后续人工补找 __ 段；提供耗时 __ 分钟（已计入谁的哪项）；用了哪些原文／译文、改了什么：
```

人工候选只记相关性，不记成自动召回率；没有完整检查视频，不能报告全部漏检数。

## 4. 顺手记业务量

从首笔基线开始，到试点结束，审核人每天留一行，范围为同一团队实际收到的全部视频核对任务，不只包含入选任务。非视频反馈不计入。

```text
日期：__；首次交稿 __ 笔，修改返稿 __ 笔；其中初始已有书面要求 __ 笔，只有口头要求 __ 笔，无明确要求 __ 笔。
```

书面与口头混合但已有可核书面要求的任务，在每日统计计入书面，具体缺口在单笔记录注明。我据此统计首稿比例、书面要求比例和口头整理负担，不让你另算。

## 5. 辅助组开始前由我核对

- 检查真实任务是否有合法分析产物，能否使用现有 `init / show / note`。没有就明确记录入口受阻，不伪造 ID、不放宽门禁、不自动跑整链；普通清单加播放器只能算流程观察。
- 按语言、时长、要求数量及书面要求情况，为 3 笔辅助任务各选一笔不同的基线参照。开始核对前固定，不看耗时结果选参照；不可比就记录信息不足。
- 整理出处、视频版本、候选时间、反馈版本和必要技术记录，不要求审核人填写哈希或证据 ID。
- 所有人工作时间相加得到总人分钟，一次性准备成本也计入并分摊；另报审核人用时、等待和任务历时，不把转移工作量当成省时。
- 如实际保留片段到 C，由该任务内容负责人在收口时整理；不要求每笔入库，整理时间归入原任务。

## 6. 结束与暂停

按已同意的门槛执行，不在结果出来后改数字：

- 最多 3 笔基线加 3 笔人工辅助，不额外凑样本；新增模型调用为 0。
- 三对节省比例的中位数至少 20%，至少 2 对更快，且没有一对总人分钟增加超过 20%，才满足效率门槛。
- 新增流程引入 1 次实质错误反馈，或遗漏 1 条已核准的必须要求，立即暂停核查；发送前发现也计数。单纯措辞润色不计实质错误。
- 达标只支持讨论下一笔页面投入，不证明自动定位有效；未达标或材料不可比，不开发页面、不自动追加试点。

试点结束由我输出一张对照表和继续／暂停理由。只需审核人确认记录准确，不再要求重标视频或另写总结。
