# Flayr 产品需求：作者内容策划与反馈工具

- 版本：v0.7（同步冻结方案v1.1的执行与统计澄清）
- 日期：2026-10-18
- 对象：产品、商务、内容及开发团队
- 状态：职责与运行方案已收口至[Flayr升级冻结方案v1.1](flayr-upgrade-frozen-plan-20261018.md)，本文同步详细执行口径；与冻结方案的产品定位/职责/首轮范围冲突时以冻结方案为准，不覆盖生产合同。本轮仅文档修订，尚未开发、启动试点或授权发送，不宣称稳定成稿、自动检索或业务省时已验证。原明确要求核对试点保留在附录A/B，不作为升级后全业务的开工顺序。

## 1. 产品目标与已确认决策

Flayr 围绕一位作者对一款商品的持续创作，组合商品理解与带货表达知识，提供拍摄策划、交稿反馈和后续内容方向。商业目标是帮助产出有购买说服力的内容；当前直接验证理解及拍摄负担、表达质量、实际使用和团队成本，不承诺成交提升或自动判断差几档。S1–S6用于整片理解和查漏，不是强制齐全的六段脚本。

| 方向 | 业务职责 | 产品形态 | 优先级 |
| --- | --- | --- | --- |
| A：内容诊断与反馈 | 对照实际发出的材料和明确约定核对表达；结合商品及整片形成待审诊断和具体反馈 | 内部核对及反馈稿；不以自动评分为前提 | 初期优先明确核对，诊断先作为待审草稿，不自动放行 |
| B：内容策划与拍摄方案 | 服务拍摄起步、内容调整与同款持续创作，形成方向、脚本或镜头方案 | 一页起步包、脚本、拍摄卡或报告页，按需要选择 | 首轮验证一款商品的起步帮助，不一次建设全部触点 |
| C：共用商品与参考资料 | 复用商品地基形成商品内容简报，关联已核参考、实际反馈及反例 | 现有文件和链接；不是独立作者产品或新数据库 | 随真实任务维护；简报复用不替代具体输出审核 |

保留ABC，不增加D：C是共用底座，A/B是业务工作。它们不是三个独立应用；不因职责升级新建页面、服务、自动接口或重排仓库。

### 1.1 作者在什么时候收到什么

| 时机 | 作者收到什么 | 发送方式与负责人 |
| --- | --- | --- |
| 拿品时 | B轻量起步包：购买理由、可改编的拍摄方向与脚本；有合适现成心译时一起给 | 在已确认合作及发送范围内，由原商务主动发；不等待新心译制作 |
| 拍摄中需要具体示范 | B脚本配合已有真实片段/截图，帮助理解想表达什么 | 作者来要时由原商务接需求，内容人员定稿后给；当前人工选片，不承诺自动逐镜头检索 |
| 发片前自愿发来 | A事实核对与需要内容负责人确认的反馈 | 作者自愿发来时回复，不主动布置考试或要求返稿 |
| 发布后48–72小时 | Rootify先检查数据；需要时给A的内容发现及B的改法、后续方向或现成心译 | Rootify/运营主动检查，不等作者求助；有值得交付的结论时由原商务主动跟进，具体分流见6.2 |
| 每半月、每月 | 由Rootify既有业务产出合作回顾、橱窗报告；按需引用Flayr内容 | 原商务按已有合作节奏主动发，合并相关拍法内容，不另重复推一份 |

48–72小时是发布后首次检查时点，不是统一判断成败或视频成熟的截止线；缺数据、价格/推广条件不明时记录限制，不自动给内容处方。此表是运行约定，不代表已实现监控、已具备心译成片或已发送。

### 1.2 联系上限与可改编原则

每位作者每款商品在本轮试点/明确的一轮商品合作中，默认主动内容推送2次（拿品帮助、发布后有价值的跟进），最多3次；不是必须发满。本轮起止预先明确，不自动重置。报告/回顾中另发的新增拍法计入，纯经营回顾不因提到商品就计入；同一次发送合并材料只计一次，不以不同产品名绕过上限。作者主动求助后的必要回复和错误材料的必要纠正不受推送额度阻断，不借此追加无关推广。跨商品消息由原商务统筹，单商品上限不是允许密集联系的额度。

简报和脚本先写清“这一段要让观众理解/相信什么”。保留具体镜头、动作与话术作可改编示例，便于拿起来拍，但不把统一画面、顺序或台词强加给所有作者。明确合作约定另行标识，不能为防同质化退回只有抽象原则的脚本。

已确认的范围：

- 业务优先级先看作者当时需要，不能预设作者不会拍。可能缺理解、方向、时间、样品或意愿，后几类不靠拍法建议解决。复用原商务沟通，不新增作者问卷。2026-10-15关于首稿较多的口述只适用于原明确要求核对试点，不作为升级后全部业务的统计依据。
- A 可以直接接受聊天要求或脚本，不依赖 C，也不要求先制作心译。
- B 可以使用本人视频、已核参考或已确认的商品信息，不必等 C 建成。
- C 向 A、B、ClipMentor 提供共用材料；已有合适资料直接使用，不要求先建完整库或补齐全品类简报才接任务。
- 隐藏评分是业务呈现和目标选择，不授权删除旧代码、放宽校验、修改生产路由或静默切换现有运行命令。
- Skill 在背后组织任务，不作为商务和内容人员的主要操作入口。
- 本文不授权新增模型调用、修改标尺或 GT、重跑历史视频、变更生产线路、对外发布或仓库合并。

## 3. A：内容诊断与反馈

### 3.1 用户与任务

分两种入口：明确约定核对，以及学习交稿辅审。收到视频时绑定作者实际收到的材料版本，不把当前最新版反套成旧要求。教学和storyboard只是参考时，不构造必拍清单；此时按[学习辅审](learning-review.md)形成待审判断，不宣称已做明确要求验收。

明确核对首版以一笔任务、一条成片、一份核准要求为单位。先查有无对应表达、证据在哪里；重点诊断单列为需要内容负责人确认的草稿，不自动产生完成结论。仅要求核对的原陪同试点及页面投入门槛保留在附录A/B，不是本次起步包试点的前置条件。

首稿的“改编是否合理”主要由人判断，工具能分担的比例可能低于修改返稿，目前没有数据证明。试点单独记录这类要求的数量、判断用时及是否获得工具帮助，不预设定位就是最大负担。

以下3.2–3.7保留明确要求核对的输入和目标界面规范，尚未建设页面；不能套到只有教学参考的学习辅审。

### 3.2 输入

| 输入 | 要求 |
| --- | --- |
| 首次成片 | 明确视频身份与版本，不混用其他作者或旧版本素材 |
| 脚本／拍摄要求 | 保留原文和来源；接受聊天原话、脚本、分镜中的明确要求 |
| 心译教学点 | 仅纳入已经明确选定并交代作者执行的点，不把教学视频全部技巧变成要求 |
| 商品背景 | 仅提供理解任务所需的已确认信息；营销宣称不能补成视频事实 |
| 原声、字幕、译文与已有截图 | 能合法复用时复用；来源、缺失或处理失败应可见 |

要求分为“必须表达／明确约定”和“参考拍法／允许改编”。分类由内容人员确认，系统不能自行把建议升级成必须项；来源模糊或有冲突时，先核准要求，不直接评价成片。

保留原清单及条目关系。需要拆分、合并或重写时由人确认，不静默改变作者收到的要求。

没有书面要求时，由审核人先把原口头约定写下，注明记录人、日期及回忆来源，并核准是否确实向作者提出过。不能事后新增要求再据此判作者漏做；记不清或有争议的内容暂不进入执行核对。记录初始有书面要求的任务比例、口头约定整理和澄清耗时，全部计入任务总耗时。若超过一半任务需要补写要求，先分析要求整理成本，不默认继续投向片段定位。

### 3.3 工作流程

以下为目标流程；陪同试点中的候选由人提供，并明确标注来源，不宣称已实现自动召回。

1. 创建任务，选择视频，导入并核准要求。
2. 准备可用的时间轴材料，显示各通道的处理情况。
3. 操作人员提供候选时间段，说明来自台词、字幕还是画面观察；尚未找到候选的要求仍保留。未来自动召回需另行验证，不以此流程描述宣称已实现。
4. 审核人点击播放、查看上下文和译文，确认候选是否相关，必要时手动补选片段。
5. 审核人记录表达问题、合理改编或可保留内容，编辑给作者的反馈。
6. 审核人确认对外文字后导出。导出不等于已发送，不自动联系作者。

### 3.4 页面要求

| 区域 | 首版内容 |
| --- | --- |
| 要求清单 | 原文、出处、要求类型、候选数量及是否已有人工记录；不显示机器生成的完成率 |
| 视频区 | 全片播放、候选时间段跳转、可继续查看前后文；截图只作辅助，动作判断必须能回看视频 |
| 文字区 | 按时间对齐的原文与译文，明确翻译来源；文字缺失不伪装成没有口播 |
| 审核区 | 候选依据、内部备注、独立的作者反馈草稿及人工确认记录 |

无候选时可以继续播放并手动选段。状态和证据解释统一遵守第 6 节。

### 3.5 定位与判断边界

- 人确认内容是否准确、表达是否清楚、改编是否合理，以及是否需要修改。
- 不按镜头、顺序或字句的机械一致性判断执行好坏；明确要求逐字保留的措辞另按约定核对。
- 不因 S1 至 S6 标签或默认时间位置排除可能相关的片段。

示例：约定为“近景展示接口插入手机，让观众看清连接方式”。系统找到插入片段后，审核人仍要判断接口是否被手遮挡。可给出“可以把镜头移近一点，避开手指遮挡”的反馈，不据此认定快充效果或执行档位。

### 3.6 候选召回与处理链路的实现约束

- 不得为了进入 A 被迫完成资格判断、Stage2 定档和作者比较报告；实现前核清现有依赖。
- 更细时间引用必须保留原视频身份、时间依据及人工调整来源，并校验越界，不覆盖原账本。

### 3.7 首版不做

双版本并排对照、修改程度评分、学习分、自动验收、自动发布、聊天系统、完整项目管理及复杂审批均不进入首版。手动使用旧视频作背景，不等于已支持双版本核对功能。

### 3.8 事实核对、诊断与对外反馈分开

核对记录使用“已定位对应表达／未找到／不确定”，处理失败另记；只有完整核看相关范围和必要声轨，或有明确范围的人工核实，才能写“确认未拍”。样本截图不支持全片缺失断言。“已拍到”不等于表达清楚或要求满足，不据这些状态生成阶段完成率。

每条针对现有视频的反馈绑定来源时间和适当截图；动作、承接和全片缺失的判断还需相关片段或覆盖记录，不能强制一张图证明全过程。纯新拍法另标分析提议，不伪装成画面事实。

学习辅审保留商品与整片检查：有涂抹不代表目标部位正确，有结果意图不代表结果清晰。主要问题、合理改编及优先顺序由内容负责人确认，不自动评分，不硬凑“一条优点加一条问题”。A是可选回应，不要求作者参加小测，不以回传视频作为获得起步帮助的门槛。

## 4. B：内容策划与拍摄方案

### 4.1 任务与输入

B承接已确认的拍摄意愿、求助或经营安排，回答下一条值得表达什么购买理由、具体怎么拍。拍前准备、发布后调整与持续创作共用同一职责；橱窗报告页只是出口之一。选品、复拍安排及联系由运营/商务负责，Flayr不自动替其决定。先确认帮助的是理解、角度或表达问题，不把缺时间、样品或意愿统一归为不会拍。

可以使用本人一条视频、同人同品多条视频、已核参考片段，或已确认的商品信息。自对照是可选方法，不要求每页找出整条视频的赢家，也不以销量高低作为内容好坏的答案。

用同款视频的业绩高低选材时，先查相同统计范围的播放量、广告投入及已知活动/规格差异，区分成交差异和内容差异。条件明显不同时，不用销量排序拍法优劣，也不把销量差距主要归因于投流；推广数据缺失不当作零投入或自然流量。条件接近只能减少部分干扰，仍不能单凭相关性证明内容造成成交。

以上限制针对业绩解释，不禁止内容对照：无论曝光或投入是否接近，都可基于原片比较具体表达、已有贡献和可迁移做法，不要求选出整条视频赢家。不能因为无法做销量归因，就放弃检查本人视频中有用的内容差异。

### 4.2 按当前需要交付

有本人视频时先做相关整片及商品判断，没有视频时基于商品资料形成明确标为提议的内容方向，不冒充个人诊断。再围绕一个主要方向组织轻量交付，可包含必要的多个镜头，不限制为一个局部技巧。可选形式是一页起步包、镜头提纲、改编脚本、手机卡或报告页，不同时默认发全套。内容包含：

- 商品及本次要表达的使用场景或购买理由。
- 一张或少量相关真实截图，内部可追溯到原视频和时间点。
- 已有做法中可以保留、复用或迁移的部分，有依据时才写。
- 能完成该方向的具体场景、动作、表达和必要结果镜头，由人确认后交付。

不固定图片、参考视频、场景和镜头数量。多场景只有在新增有用信息时才选；替代场景以降低执行负担为目的，不借替代项增加卖点或任务。资源条件依据本人实际材料或确认，不从过期画像推测其有宠物、孩子或车辆。

需要解释动作过程时可附可访问的片段；不强迫静态截图证明动作全过程。

没有本人相关视频时，可以给明确标为提议的拍法，不评价本人缺少什么，不编造截图，也不冒称完成了本人视频诊断。没有值得保留的已核内容时不硬凑对应段落。

### 4.3 输出边界

- 复用 C 中的片段仍须检查商品、作者条件和本次用途；入库不等于所有场景都适用。
- 不把已经拍过的内容重新包装成缺失项，不把旧商品的画面和性能当作新商品效果证明。
- 不承诺补拍后提高多少销量、完播率或达到爆款表现。
- 按收件人及用途执行共用表达和人工定稿；报告页再沿用报告排版，不将报告格式强加给起步包或聊天反馈，不新增独立应用。
- 作者版按[共用沟通规范](creator-communication.md)以“可以……”“可以试试……”提出具体做法，默认“你的视频”“同款参考视频”；有明确业绩来源也不能自动归因到具体拍法。内部阶段编号、档位和处理状态不进入作者版。

示例，仅说明结构：若画面已经核实挂包携带的展示，可以写“挂包携带的展示可以保留。可以再补一个外出时给手机接上充电的近景，让便携用途更具体。”这不是对某条未检查视频的现成结论。

### 4.4 可观察的交付反馈

内容负责人记录定稿修改量。建议实际发送后，由原商务联系人随下一次自然沟通记录：是否追问拍法、能否正确复述，以及下一条相关视频是否采用并清楚表达。若该视频进入 A，引用同一份核对记录，不另做重复审核。

无追问不等于理解，出现一个动作不等于建议已经表达清楚；没有回复或没有后续视频记为未观察，不记成功或失败。采用记录不能证明销量改善。本节不授权主动发送或新增催问。

### 4.5 不等待心译成片的轻量起步包

需要拍摄帮助但心译尚未完成时，先用已有商品简报、真实截图/时间点及文字脚本或镜头提纲。来源不足不伪造截图，可给明确标为提议的拍法；不写成已完成本人诊断。只有真实约定才标必须镜头，其余标参考/可改编。

这份材料不是心译成片或已验证的可视化脚本，不等待视频也不替ClipMentor制作。心译完成后由原商务按实际需要补充，不重复推送同一内容。原片storyboard保持原片忠实；为作者新设计的脚本单独标“改编提议”，不能混为原片表达。

## 5. C：共用商品与参考资料

### 5.1 核心对象与用途

C以已有商品地基为基础，按商品形成可共用的内容简报，关联参考片段、实际反馈和反例。不是新库或新产品，不重新给全库打标，也不把散落信息一律复制到Flayr。简报记录必要结论并链接原出处；原经营数据、标签由Rootify Agent维护，心译作品由ClipMentor维护。

资料用于策划、辅审、找参考和准备心译。先整理实际要用的一款商品，不批量补简报或重分析历史视频。一条原视频可关联多个片段，认可局部不表示整片优秀；不以收藏量证明价值。

C分两类，分别维护，不把原片、主张、确认结果混成无差别素材库：

| 类别 | 粒度与产生方式 | 更新与复用规则 |
| --- | --- | --- |
| 商品内容简报 | 每款商品一份适用版本，复用地基后主动整理；相关SKU差异明确 | 由指定维护人按商家资料变化、事实纠正或新参考线索复核，确认后升版本；新增爆款只触发检查，不自动改写购买理由。具体失效按5.6 |
| 参考片段和案例 | 每条来源绑定的表达判断一条记录；在A/B/ClipMentor实际工作中积累 | 每次实际复用记录用途、对象、日期及反馈；新情境只确认新增适配范围，不因被复用就自动提高可信度。旧判断被纠正时保留历史并标明当前结论 |

两类用链接关联：简报引用适用的片段判断，片段记录自己被哪份简报/任务使用；复用记录不等于简报内容变更，不要求每次升简报版本。

### 5.2 每个参考片段保留的信息

| 信息 | 内容与限制 |
| --- | --- |
| 来源 | 原视频身份、文件或可用位置、起止时间、真实截图；来源不可用时显式提示 |
| 商品背景 | 原商品、品类及与该片段相关的已确认信息 |
| 画面与声音 | 观察描述、原声文本、字幕及可用译文；注明核查状态 |
| 拍法 | 实际景别、动作、口播配合和所需拍摄条件，不套固定镜头模板 |
| 借鉴点 | 人认可的具体用途、理由、确认人及适用范围 |
| 限制与反例 | 不适合迁移的情境，不能由该片段证明的事实 |
| 使用记录 | 用于哪次脚本、心译、核对任务或报告，保留实际采用情况 |

历史判断优先整理为带来源、情境和反例的案例笔记，不直接压成新的通用评分手册。相互冲突的记录保留各自出处和后续修订，不把旧结论静默改写成一致。

### 5.3 查找与操作

目标是围绕商品、想表达的信息、拍法、拍摄条件及审核状态找片段。当前先人工查已有文件和索引，不宣称已有自动按镜头检索。S1至S6只作辅助标签，不是唯一分类，也不强制每条素材只归一个阶段。

页面形态可以提供浏览、筛选、播放、查看原声译文及选择引用。初期资料少时先采用现有文件和清单，不把建设独立数据库、向量检索或新服务作为前提。

需要跨商品引用时，同时展示原商品和拟用商品，保留适用性说明。没有匹配材料时允许返回没有合适参考，不硬凑一个最近的案例。

### 5.4 与 ClipMentor 的职责边界

Flayr 提供来源片段、事实、已核借鉴点和限制。ClipMentor 决定教学选点与组织方式，并制作讲解、字幕、标注、配音和分镜。

交接资料不能代替 ClipMentor 的制作、听审和成片验收；ClipMentor 中的人工作品认可也不能反推为 Flayr 的自动检索已验证。具体文件格式在接口实现时核定，不新建第二套视频编辑器。

### 5.5 积累责任

A 的审核人、B 的内容定稿人或 ClipMentor 的内容审核人在确认片段确有复用价值时做标记；该笔任务的内容负责人在任务收口时补齐出处、借鉴点和适用限制，缺项保持待整理，不进入已核参考集合。每笔任务启动时记录负责人姓名，不另设专职库管理员，不强制每笔入库。

标记、整理和复核的用时归入来源任务的总人工成本，同时单列为素材积累用时。独立补录历史资料另记成本，不把资料积累当成免费收益。

### 5.6 商品内容简报：确认、复用和失效

每款按商品ID识别；规格或配方影响用途时分清适用版本。由本笔内容负责人整理并指定简报维护人，业务负责人在实际使用前落实姓名，可由同一人兼任，不新增岗位。内容定稿人确认购买理由、表达路径和参考适配；品牌/商家确认过的口径保留原确认者及出处，不由内部人员冒称品牌核准。

| 内容 | 记录与边界 |
| --- | --- |
| 商品身份与版本 | 商品ID、名称、相关SKU/适用范围，简报版本、日期、维护人与确认人 |
| 核心购买理由 | 少数重点、商品地基及来源；区分商家主张、已观察、人工确认、分析提议与未知 |
| 表达路径 | 商品特点如何进入吸引、讲解/使用、结果、信任与购买引导；不是六段必拍模板 |
| 可选方向 | 不同问题、情境或对象及表达目的；不硬凑2–5项，同一购买理由可有多种表达 |
| 表述边界 | 现有来源支持的说法、已明确限制和待核项，保留出处；商家主张不等于效果或合规已验证，不凭空补绝对禁语 |
| 参考与修正 | 原片/教学版本、时间点、适用条件、反例，以及后续事实纠正的出处 |

审核状态为“草稿／已确认范围／相关内容待复核”，记录确认的是哪部分，不笼统写整份全部可靠。源材料未变、用途未变时直接复用；换作者后的个人事实、场景、翻译及脚本仍检查相应新增内容。简报已确认不等于后续作者稿自动可发。

商品身份、配方/规格、用途或口径发生实质变化，或出现事实纠正时，维护人提升版本，标明受影响条目；原版留档，不再作为新任务的该部分依据。已生成但未发的相关稿件暂停相关主张并复核，已发送材料由原商务和内容负责人判断是否需要纠正；不让代码自动修改旧稿或重新发送。只有链接暂不可用时标来源待恢复，不把它等同商品已失效。无关改句不让所有材料全量失效。

这是文件级维护要求，当前没有自动依赖追踪、失效传播或拦截功能。缺确认人或来源的部分不能当作已核口径；不要求取得完整说明书才整理拍法，不将无关专业参数缺失设为全页阻塞。

### 5.7 Rootify商品标签的有限作用

标签只用于同ID/相近功能和对象检索，以及连同标题依据提供用途核查线索。场景标签覆盖不全，标签缺项不等于不适用；标签、标题也不是所有用途的绝对上限。具体使用提议需有相应商品信息、已核使用材料或明确确认支持，不由泛功能标签推出具体性能。

购买问题、钩子、结果镜头来自商品地基与素材分析，内容重复来自视频历史；这些不算标签贡献。不用旧画像推断作者生活条件。下一笔B在内部记标签找到的有用参考或实质改变的建议，没有就如实记无；若持续无帮助，不把读标签设为B必经步骤。C保留索引，不新增字段体系或全库打标。

## 6. 三方向的关系与共用要求

```text
C：商品内容简报＋参考＋已核反馈
  → B：准备拍 → A：看实际交稿 → B：下一条方向
  ← 实际使用中有依据的修正与参考，人工收口回写
```

这是一段按需启用的合作过程，不是三套应用或必走步骤。入口、页面和接口本次不设计或开发；先在已有任务记录中用文件和链接交接，不跨仓库复制分析器、经营报告或编辑器。

共用要求：

- 每条判断能追溯到具体来源；视频、要求或素材变化后，不静默继承旧审核。
- 内部备注、机器候选、人工确认和对外文字分开存放与展示。
- 候选相关不等于满足要求；局部命中不代表全片覆盖。人工判断质量，系统不自动完成或评分。
- 截图和文本必须对应同一视频及真实时间；找到帧只证明来源对应，语义是否支持结论仍需核实。
- 口播提及动作不证明动作发生，展示图标不自动证明产品效果。事实已核、借鉴点已核、拟拍建议分开记录，已有画面和拟拍内容不混写。
- 不把译文当作无误的原始事实。出现影响要求含义的歧义时，保留原文并交人工确认。
- “未找到候选”“处理失败”“尚未人工核对”分开显示，均不能自动变成没做。
- 商务聊天、作者视频和内部素材默认用于获准的内部任务，未经授权不公开分享或自动发送。
- 不从商品一般功能、营销卖点或历史销量补造本条视频的事实与因果结论。

### 6.1 面向作者的交付审核与效率

只要最终给作者看，A反馈、B报告页、C参考卡/脚本/教学交接均执行[共用审核机制](creator-communication.md)。内部资料无需逐份作者化，但引用到作者产物时检查当前上下文。

审核并入已有内容定稿，由同一负责人一次检查表达、事实与图文、可执行性，不设独立审批队列。作者纯文本或Markdown用现有`--author-copy`独立扫描，无需A的教学包；HTML/PDF及音视频仍在相应交付环节核实际可见或可听内容。

原任务备注留一行最终文件/版本、审核人/日期及可发/待修改/待核事实；自动扫描不授予可发状态。修改后只复查受影响内容与上下文，已核且用途未变的来源材料复用；新作者、商品、用途、语言或关键证据变化则检查相应适配。可发不等于已发送。

只为必要核事实或最终采用询问业务方，执行者先修可自行解决的用词问题。不新增模型调用、重跑视频或要求用户重填判断。人工投入并入现有定稿耗时，实质错误与普通措辞调整分开记录，不建立额外逐句填表负担。

### 6.2 触发、请求负责人和发送时机

以下是人工运行约定，不是已接入的数据监控或自动推送规则。运营用现有追踪发现信号，由原商务确认作者当前需要后提出请求；没有拍摄意愿或卡在样品/时间等条件时，不自动补脚本。每笔落实原商务、内容定稿人和必要的产品口径联系人姓名，不默认新增角色或岗位。

| 信号/需要 | 谁提交请求及必要上下文 | Flayr返回什么 | 谁在何时发送 |
| --- | --- | --- | --- |
| 拿品/准备拍，作者希望得到理解或方向帮助 | 原商务：商品、作者当前需要、已有材料及拍摄安排 | B轻量起步包；需要教学时附ClipMentor现有材料或提出制作需求 | 原商务在作者准备该款时合并发送，不等成片才能帮助 |
| 作者主动发来首稿/求助，或合作中有已约定核对 | 原商务或内容负责人：原视频、实际已发材料/版本、明确约定与参考的区别 | A证据定位、事实核对、待审诊断及具体反馈 | 内容负责人定稿，原商务按本次请求回复，不另设考试 |
| 运营发现有曝光但成交有限 | 运营提供日期/窗口、播放/订单、可用点击及推广/报价信息；原商务确认是否需要内容帮助 | 检查可用信息后给待查原因、相关内容发现或一个新方向；不能默认归因为S3–S6 | 原商务在有可执行结论且适合沟通时回复；信息不足只限制相关结论 |
| 开始出单且作者准备继续拍 | 运营提供同口径数据；原商务确认意愿、资源和下一次拍摄问题 | B保留已有贡献并给有意义的新方向，不自动追加3–5套脚本 | 原商务在下一次准备拍时发送，不把出单自动变成任务 |
| 同款多位作者出单，运营考虑扩大合作 | 运营发起候选讨论，核推广/时间条件及资源，由商务确认对象 | 可迁移表达与适用条件，不把共现当因果或承诺跟拍能爆 | 合作安排由运营决定，原商务按对象需要发送，不自动群发 |
| 播放低、原因不明 | 运营提供观察条件；商务确认是否有具体求助 | 有证据才给内容分析；不默认是S1，不强行动作 | 不因低播放自动推建议，原商务选择沟通时机 |
| 阶段复盘/橱窗报告已有内容需求 | Rootify报告/合作回顾负责人提出具体作者、商品、决定和数据窗口 | 可引用的内容发现、画面及B方案 | 原报告负责人整合，原商务按原有报告/回顾节奏发送 |

Rootify/运营负责发布后48–72小时的主动首查，并按本轮已约定的后续观察安排跟踪。对照同款其他作者的视频判断相对曝光/成交情况时，保留相同观察口径及可用的投流、价格、活动、人群/账号条件；这些只是背景与分流依据，不证明内容原因。推广缺失不当零，找不到可比对象则注明，不为了分流强排高低。

运营在原任务记录中提出“内容复核A／新方案B／两者结合／暂不介入”的请求及依据，注明原视频、截至时间、同款对照与已知干扰，内容人员接手后再判断表达问题。没有自动API或通知实现时先由运营人工交文件/链接，不等待新系统；不能只记背景而漏掉主动首查。

不以固定1000播放、经过48–72小时或跨作者销量名次直接决定改法。数据不足可以继续观察，不自动归因S1或S3–S6；发送是否值得由原商务和内容负责人结合结论判断，主动发送遵守1.2的默认2次、最多3次上限。

### 6.4 反馈回到C：一行记录而非新表

原商务/运营在正常沟通或观察到后续视频时，沿用原任务备注记一行；内容定稿人补表达核对和来源，由简报维护人在收口时处理。作者不用填表，不要求每条无新发现的视频都入库；每次实际复用已有片段/案例仍在该任务中留一次引用及反馈链接，不另抄一份案例。

```text

```

采用必须有可定位的内容依据；只有作者口头说会拍，记意愿，不当实际采用。未采用的原因有反馈才记，没有回复或还没新视频记未观察。商务不确定表达是否成立时交内容负责人，不自行将动作命中判为有效。反馈是提议/线索，不自动升级成通用规则或重写已核简报；商业成绩不能自动证明某个镜头有效。

### 7.1 范围和前置决定

这一条件是本轮选样安排，不是所有商品未来都必须满足的门槛，也不代表5人足够证明效果。不等待新心译、不先建页面、自动检索、实时监控或素材生成；ClipMentor有合适现成材料就接入，没有不为本试点专门制作。

### 7.2 记录口径与观察安排

分别记录拿品及起步包发送日期；每条实际发布后48–72小时由Rootify/运营首查并提交是否跟进的请求。整轮收口日期结合启动时已知拍摄安排预先固定，不把上一版建议的“发送后7/14天”继续作为当前统一窗口；未定收口日期不启动统计试点。检查不等于再次联系，主动发送仍受1.2约束。超出观察窗口、没有后续视频或信息不足记未观察，不自动换人凑结果。

首查时没有新数据，记录“已检查、数据不可用”、旧快照日期、缺项及下一检查负责人/时点，不判零单或低播放；不依赖数据的明确内容求助可继续。可比时优先对齐发布后视频龄期，并保留日期、单位、推广/价格背景，历史累计快照不冒充48–72小时表现。未发布或数据触发未发生不能称完整闭环通过。

采用情况是首要使用指标；质量是放行条件，成本是继续投入条件。启动前锁定起步组及分母，分别报计划参与、发出、愿意、建议后续出现、可确认采用、表达清楚人数。确认采用人数/固定起步组人数是已确认下界，另报可观察作者中的比例及全部未观察人数。按作者/商品/实际发出版本/后续视频关联：既有拍法记延续，拍摄先后不明只记对应表达出现；可确认关联需已有稿、明确拍摄时间或作者反馈等依据，不要求作者另填证明表，也不宣称因果。后续补发方案单列，不计入起步包成绩，一个作者多视频不重复计人。

| 记录 | 最小口径 |

### 7.3 暂停与后续投入

首次出现新增流程导致的实质错误对外反馈，或确认简报事实有误，先暂停受影响材料复用和发送并核查；不抹掉已经发生的错误。未发送前发现的实质错误同样记录并退回相关稿，不当作质量通过。改句不自动扩大成整款全部停用。

### A.3 数值门槛与停止决定

以下为保守的投入门槛，不是由历史数据估计出的能力指标。启动前确认并记录版本，开跑后不得因结果不好调整；变更须作为新的试点提案。

| --- | --- |
| 样本与投入上限 | 固定 3 笔现行流程、3 笔人工辅助流程，新增模型调用为 0；不足或不可比记为信息不足，不追加任务凑通过 |
| 效率 | 按预先选定的参照计算每对节省比例，三对的中位数至少 20%，至少 2 对更快，且没有一对增加超过 20% 的总人分钟；三项都须满足 |
| 输出安全 | 发生 1 次由工具或新增整理流程引入的实质错误反馈，立即暂停试点核查；无论发送前后发现都计数，不继续凑满 3 笔 |

节省比例为“基线总人分钟减辅助总人分钟，再除以基线总人分钟”。总人分钟包含陪同、文件整理和分摊到该组三笔任务的一次性准备成本；不能只比较审核人坐在播放器前的时间。普通措辞润色不算实质错误；错视频、错时间导致错误判断、把未找到写成没做、扭曲要求或功效等算实质错误。

B 以第 4.4 节的实际反馈记录可用性；C 以真实查找和采用记录复用价值，不以页数、入库量或销量增长验收。两者有独立开发投入时再分别预定门槛，不借 A 通过自动获得批准。
