## 一、最终定位

2026-10-16最新业务确认（取代此前等待范围确认的限制）：用户明确“使用情况和效果是必备的，before/after”，作为本次 PAPA FEEL 学习辅审的内容要求。厂家卖点和特点只是参考，要结合当地消费者的需求与场景，判断使用和结果表达是否把产品价值讲成立。继续分析不以等待厂家口径为前提；具体见效时长、功效幅度等宣称仍不能自行核准。复用现有商品地基的场景、消费者结果、可观察信号及证明条件，不另造评分体系。

这项业务确认不等于确认每条视频缺少对照，也不等于四条建议都应写成“补前后记录”。01的缺失已有用户确认；02已有两侧观察表达；03–05仍按各自材料判断存在性、支撑范围和最值得改的内容。04的24–37秒、05的46–52秒已完成局部全帧图像核查，原声未听审；不能称完整视听核对完成。现有暂存回复仍待逐条更新核对，不自动转为外发稿或计时验收稿，详见本批 `product-review/target-frame-review/review.md`。不预设必须跨日、即时见效或要求停拍攒记录；也不改变全局 S3/S4 合同。

业务背景：团队把爆款拆解视频发给作者学习，storyboard 是配套的文字框架，供拍摄时使用，不是已确认的逐项必拍清单。

本场景的 A 定位为“学习交稿辅审”。输出按三步组织：**落在哪里、落得好不好、怎么改**。中间一步有质量判断，不能声称取消档位就已经解决可靠性。结合商品地基、已确认业务要求与教学目的判断整片产品价值表达，由人确认；教学外的分析提议另标来源，不伪装成教学原话或必拍要求。

这份方案调整了 `flayr-abc-product-requirements-20261015.md` 中 A 只接受明确约定的范围：本试点允许教学参照，但不产出约定完成率、未执行要求、学习得分或 small/medium/large。原有明确约定核对仍保留，不能把教学参照伪装成强制要求注入现有命令行。

A 的核对依据与 B 的下一条拍摄建议共用一份回复，内部仍分开保存；人工认可的片段可成为 C 的待入库材料，不自动入库。

## 二、教学依据怎么来

借鉴点直接从完整拆解教学中提取，不另选一套评分维度。storyboard 仅帮助查找及对照，不能覆盖教学里另一条参考视频的内容。

每个借鉴点保存以下内容：

| 字段 | 内容 |
| --- | --- |
| 来源 | 教学文件哈希、时间段、对应参考视频、原话；译文另列 |
| 目的 | 教学明确解释的“为什么这样拍”；没说清的就记未说明 |
| 做法 | 教学实际演示的拍法，不自动视为唯一实现方式 |
| 核对问题 | 由上述目的产生的可观察问题；推导内容明确标为审核辅助，不冒充原话 |
| 边界 | 替代拍法、仅凭画面无法确认的内容、功效或营销宣称待核口径 |
| 审核 | 内容负责人确认或改一句，注明版本；未确认不批量评价交稿 |

同一版本教学只核准一次，服务本批五条，之后才考虑扩到其余视频。核准内容是否正确，不要求负责人重新选借鉴点；不能预先承诺这一环成本很低，实际计时。

例：若教学说“让人看清质地”，核对的是画面是否能支撑这一目的。“近景、膏体可见、涂开连续、手不遮挡”可以帮助观察，但除非原话明确要求，否则不变成必须全部满足的四项门槛。

## 三、逐条辅审

### 0. 先判断整片主问题

围绕本条产品诉求，先写“已有购买理由、关键支撑缺口、为什么优先改这里”。钩子、引出、讲解/使用、结果、信任、购买提醒是功能检查问题，不是六项打勾或固定时间顺序。商品背景、教学、视频事实及内容推论分别注明；无法核实的点不冒充缺失，但已经由用户核对的缺失也不能继续搁置。后续局部拍法必须服务这个主判断。

本批 `product-review/cases.json` 每条必填 `whole_video.intended_belief`（要让人相信什么）、`established_support`（已有支撑）、`priority_gap`（首要缺口或尚待核实之处；充分时明确无需补强）。交接前执行同目录的 `validate_cases.py`，现已统一转调仓库检查，同时检查商品依据、教学联系和事实出处。字段口径与复用顺序见 [学习辅审执行入口](learning-review.md)。缺字段、空白或错误类型会失败；填满不等于判断正确，不据此自动放行。未知事实不能靠填字段补成结论。

### 缺失结论的证据标准

| 可用表述 | 最低依据与边界 |
| --- | --- |
| 没有展示某项内容 | 已连续核看完整相关范围，并核对必要音轨、字幕与疑似短片段；或已有审核人针对同一视频、范围和目标的明确人工核实。记录文件、范围、核实人及来源。不要求逐帧机械检查，但不能只是对抽样结论点头。 |
| 在已查材料中未找到 | 只看抽帧、1fps全时间轴和ASR，或关键范围尚未核完。写明查了什么，不能升级为全片缺失。完整转写不补足视觉覆盖。 |
| 已有展示，支撑有限或尚不清晰 | 真实片段已经出现，但画面、关联或可比性不足。不能因为短暂、不充分或缺少前后对照就改写成没有。 |

不设置“持续几秒以上才算”的统一门槛。短暂真实结果也有贡献；连续动作可能落在两张样图之间，样图中的对象状态也不自动是产品结果。先核是否存在，再判断具体支撑了什么。

上述区分不阻止整片分析：即使尚不能断言缺失，也可以指出“已核的手背质地材料只能说明质地，不能支持所说的眼周变化”，将结果支撑列为优先待核点。此时不给作者发送“没有结果”或“补一个原本已拍的对照”。只让审核人确认具体未闭合事实，不让其重新构建分析。

01 沿用本轮用户对整片的明确事实确认，不补写其未记录的观看方式与耗时，也不重复追问。02–05不能继承01的确认。

### 1. 落在哪里

- 每条交稿完整查看画面，并对照完整转写；涉及关键语义时回听原声。抽帧用于找候选、截图用于举证，不能代替连续看片。
- 按借鉴点记录一个或多个候选时间段，保留截图和原声/字幕依据。拍摄顺序不同不扣分，不能按 storyboard 的秒数套交稿。
- 区分“有对应片段”“尚未定位”“处理失败”“尚未核对”；后二者不变成未做。
- 本次人工找出的片段不计作自动召回成绩。ASR 只是待核转写，不当作听审完成。

### 2. 落得好不好

- 结合本品购买疑问、已确认业务要求和教学目的，解释现有内容支撑了什么、重要缺口在哪里，再看动作是否可辨、画面是否支持信息。不得把判断收缩为教学拍法的构图检查；教学以外的内容推论单列来源。
- 结论需要指出具体事实，不计算条件满足数、不加总、不打档位。
- 允许替代做法。例如评论图与销量图都可能用于信任表达，但是否达成目的仍看本条内容，不能按素材类别自动等价。
- 同时保留做到的部分和无法确认的部分。看见动作不等于看见功效，问题示意图不等于本人使用结果。
- 教学条件本身有歧义或与现行业务口径冲突时，登记冲突并暂停该项评价，不为了完成表格自行裁定。

### 3. 怎么改

- 先完成整条职责和问题的内部复核，再选择值得反馈的具体拍法；数量按问题决定，不设最多1–2条的上限。已有贡献保留，不强制“先说做到的”，不为每阶段凑意见，也不把实际使用与效果两个独立问题硬并成一点。
- 修改具体片段前，要看完整片段及上下文；提出补充某内容前，要核对完整视频相关画面和必要音轨。
- 不因某动作比参考片晚，就建议提前到前 10 秒。只有教学依据和当前结构问题都成立，才讨论顺序调整。
- “下一条可以加……”不能绕过是否已拍过的核对。已拍过则认可或指出具体表达问题，不重复推荐成缺失项。
- 功效宣称是否能用，由业务提供经过适当审核的统一口径；工具不替品牌批准、否定或改写“一分钟”等宣称。

作者回复格式：

> 约〔时间段〕的〔具体做法〕，能让人看清〔已核实的信息〕，这一段可以保留。下一条可以试试〔有依据的具体改动〕，让〔明确表达目的〕更容易被理解。见图〔编号〕。

方括号为结构说明，不作为实际交付文本；不是强制先表扬的顺序。主问题已成立时可先简明说明，再落到具体拍法。无成立的改进点时省略第二句。作者版不出现内部阶段、状态、档位、“达人/标杆”；必要比较使用“爆款视频”，且明确是哪条参考片。截图只能证明静态内容，连续动作、停留时长须附片段时间，不能写成一张图已证明全过程。建议不承诺销量、流量或转化提升。
