## 1. 结论

**A 应继承 Flayr 的商品理解、整片说服过程分析、具体表达判例和证据交付能力。只保留时间轴、截图与留痕，会丢掉它最有价值的业务积累。**

暂停自动比较和定档，不等于停止分析内容好坏。A 仍然需要回答：产品价值有没有通过这条视频被具体表达，参考里的有效做法在交稿中如何体现，最值得保留或改善什么。答案要落在具体事实和建议上，由人确认；不能声称不打分就消除了判断难度。

本轮也查明，旧资产不能整包恢复。历史商业文档含已过时的位置规则、机械计分和没有足够依据的效果推断；现有代码的一些排序与强门禁专为双视频比较设计，不适合原样套到学习辅审。

## 2. A 的当前业务边界

本批主场景是“收到爆款拆解教学及 storyboard 后的学习交稿辅审”，不是检查逐镜头照抄，也不只是查明确要求在哪里。

- 商品资料提供产品信息；厂家卖点仅供参考，本地消费者、情境和表达选择需要内容判断。
- 爆款及教学提供已经讲解的参考做法和目的；销量高不保证每个做法都好。
- 交稿按实际提供的信息评价。可以辨认“与教学目的相符的表达”，不能仅凭相似镜头推断作者看过教学、真正学会或由教学造成销量。
- 用户已明确本次 PAPA FEEL 要有实际使用及效果 before/after。该项目要求不等于全局 S3 只准实际使用、不等于所有品类都须同一种对照，也不证明各条均未做到。
- 明确约定核对仍是 A 的另一种输入，不删除；不能让这一路严格的要求清单限制学习辅审。

## 4. 商品地基：最需要恢复，也最不能机械照搬

来源：[商品地基实现](../scripts/flayr_core/llm/product_profile.py)、[生成请求](../scripts/flayr_core/llm/payload.py)、[命题关联](../scripts/flayr_core/proposition_contract.py)。

现成内容远多于卖点清单：

| 已有字段/依据 | A 应回答的实际问题 |
| --- | --- |
| `category_profile.painpoints`、`physical_task`、`hook_proposition` | 消费者遇到什么问题，为什么会关心这条视频？不是所有品都要痛点开场 |
| `core_selling_points`、`usage_context` | 产品什么特点值得解释，在什么具体场景中体现？ |
| `short_video_proof_plan.candidates` | 不同卖点各适合用什么材料讲；哪些能实拍，哪些需要讲解或有来源的支持？ |
| `consumer_outcome`、`observable_signal` | 观众具体应该观察什么，而非笼统的“看效果”？ |
| `before_state`、`after_state`、`proof_condition` | 对照在比较什么，条件是否支持这项表达？ |
| `proof_contract_source`、`selection_source` | 是业务给定、人工整理，还是模型推断？不能把推断升级成事实 |

三处限制必须保留：

1. **结构有效不等于产品真实有效。** `normalize_proof_contract` 会检查字段、信号、条件和模式，但不会替我们确认实际功效。
2. **旧“视觉优先”排序不直接接入 A。** `_proof_plan_rank` 先排视觉展示空间，再排功能中心性，最后排理解成本；它服务旧证明锚点选择。A 不能因此总挑最好拍的卖点，而忽略本次消费者购买理由。保留候选和选择理由，优先级由本品、本次教学及业务信息共同确定。
3. **单一测量锚点不等于唯一商业价值。** 旧合同要求一个可复核维度，适合限定某次结果核验；A 仍应认可质地、使用便利、信任等不同贡献，不用一个结果锚点否定其余信息。

`brand_propositions.json` 是有限的人工策展命题集，不是全品类事实库；当前没有 PAPA 条目。不能假装命中经审核品牌资料，也不能照抄其他产品的主张。原 Step-0 允许模型用世界知识补字段，A 在使用这些补充时仍需保留推断身份，不能作为当地市场事实。

## 5. “落得好不好”已有比抽象评分更丰富的依据

来源：[人工尺度地图](../runs/diagnostics/human-scale-map-20260920/scale-map.md)、[执行与观众接收](../runs/diagnostics/human-scale-map-20260920/execution-communication-clarification.md)、[效果依据与表达收益](../runs/diagnostics/human-scale-map-20260920/s4-expression-and-evidence.md)，以及本机 `references/historical-contrasts-next-step-20261014.md`（未随本次发布）。

下表复用的是已记录的人工判断依据，不是本轮重新核看这些视频，也不移植历史档位。

| 历史经验 | 给 A 的具体用途 | PAPA 对应 |
| --- | --- | --- |
| BOTARE 的下抽、遇水使用与讲解，分别让人理解取用便利和使用表现 | 先说动作增加了哪项产品理解，不只数动作 | 取用、手背涂开、眼下施用各承担不同信息，不能统称“演示了” |
| LOGESKI 的短暂用途延伸与 Dr.WOW 在不同场景里的展开不同 | 多场景的价值在用途是否被说明，不在场景数 | 多部位图卡与实际使用不是一回事；一处讲透也可有价值 |
| Aavini 的关键动作在角落，说明做了不等于传达清楚 | 构图作为信息接收条件，而非独立美学打分 | 只有确定在看哪项眼周信息后，才能解释近景、手部遮挡或停留的意义 |
| CREAMY 关注提色、CARSLAN 关注上脸妆效 | 看本品相关结果，不奖励任意视觉变化 | 手背质地不能替代黑眼圈或眼周纹路的结果依据 |
| Fasclean 洁白衣物现状不等于洗净过程的结果；NIUMO 通电是有限而真实的结果 | 防止一边把普通状态当效果，一边又把弱结果全删掉 | 04 使用后指眼周不能直接叫“没结果”，也不能直接写“纹路消失” |
| 同一片段可同时引入、讲解或展示结果 | 按表达功能读片，不切成互斥六段 | 接产品时开始涂抹可以成立，不要求再补一个专门引出镜头 |
| 主动评论、实验室图、认证可贡献信任；包装顺带可见不自动算 | 检查来源、实际强调和支撑范围 | 教学里的图卡要看具体内容，不强求所有交稿添加同一种认证 |
| 双方相当仍可有共同提升方向；参考销量高不证明内容处处好 | 建议可以超出参考的不足，但注明是内容建议，不冒充教学原话 | 不把“爆款没拍”当作不能建议，也不把“爆款拍了”当成必须复制 |

A 可以沿用的判断方式是：**本品、本环节要传达什么；视频实际给了什么；表达是否让相关信息可辨；还有什么关键支撑没建立；哪一个具体改法最有价值。** 这些问题融合起来解释，不打成几项分数再相加。

“未找到”“存在但支撑有限”“已确认没有”继续分开。确认存在/缺失和判断表达质量是两个问题；范围变窄不会自动使模型可靠。历史判例用于提醒和限制推论，不自动替当前片段下结论。

## 6. 整片判断与具体拍法应接起来

来源：[整体设计与建议筛选](../PRD.md)、[产品—人—场景](../references/observation-guide.md)、[现行阶段边界](../scripts/flayr_core/stage_contract_registry.py)、[全局诊断](../scripts/flayr_core/postprocess/global_diagnosis.py)、[拍摄模块](../structure_library_full.md)。

整体检查保留六个问题：

1. 开头让哪类观众因为什么留下？这个理由与品相关吗？
2. 后面是否把这个问题自然接到产品，而不是只露出瓶子？
3. 讲解和实际使用，让人理解了哪些功能、体验和用法？
4. 所说结果具体由什么可观察材料支撑？
5. 有哪些主动表达的信任依据，分别能支持什么？
6. 已建立的购买理由之后，有没有合适的购买引导？不强制结尾或固定口令。

它们不是六项扣分表。某项问题是否成为首要建议，要看本品需求、已有表达、缺口重要性及拍摄成本；先抓主要问题，不把最容易配截图的点放在最前面。

旧全局诊断中的“卖点路线、焦点一致性、注意力干扰”值得用作检查。代码却会消费资格、占比、模型绝对状态，并生成 `blocking/major/minor` 和商业优先级；其中非首选但有证明的路线也可能得到 `minor`。A 不应直接继承这些结果，也不能把合理改编预设为问题。

问题确定后再选拍法：结构库已经提供镜头主体/景别、文案、声音与节奏，以及单场景、多场景、步骤拆解、前后对照、用户证言等选项。复用其中具体动作；固定秒数、音效“必需”、数量和品类禁用表只可看作旧模板，不能变成通用质量标准。

作者最终收到的应是“保留哪段、下一条怎样拍、让观众看明白什么”，而不是“加强产品表达”。构图仍然重要，但要服务这个目的。
