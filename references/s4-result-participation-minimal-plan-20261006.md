# S4 结果参与边界：最小修复提案

## 状态与目标

2026-10-06，源码起点 `be6b7a9`。共享定义修正与工程修复分开提交，随后机械 refreeze；资格候选未实现、未启用、未调用模型。
目标是减少“操作完成或对象当前状态被资格化为产品效果”的错误，不重写幅度标尺。
这是限定开发提案，不宣称同一根因已覆盖 40% 错误或满足跨 3 样本、2 品类门槛，
也不改变既有全自动生产晋级条件。模型验证须在用户批准本提案后才启动。

## 已核实的入口和冲突

- Stage1-A 的原始画面文字与 fact_quality.proof 已可能不一致；不能无条件相信抽象 proof 标签。
- Stage1-B/D 根据原子事实资格化 S4，Fasclean 两次最终 partial 均引用提起/拧干衣物等状态。
- Stage2 会消费这份资格包；错误参与已在上游形成，单改档位或要求 Stage2 反思不能解决主入口。
- `stage_contract_registry.py` 的 S4 是 visual_required，result_presentation 已要求本品目标相关可见结果。
- 实际指令仍存在冲突：`payload.py` 的 `_stage_group_flag_contract` 和 `phase_c_payload.py`
  把“结果叙述”也写入 result_only；`compact_eval.py` 两处写“结果口播”，另有一句明确许可结果口播支持 result_only。
  这证明定义不一致，不证明它就是 Fasclean 误判的唯一原因。
- fact_quality.proof 描述原子事实；effect_evidence_state 描述 S4 阶段效果。
  两者不能因为都使用 result_only 字样就机械等同或互相覆盖。

## 推荐做法

### 1. 单独消除明确的定义冲突

以现有 visual_required 合同为准：S4 的 result_only 必须有可观察的产品相关结果画面，
只是因果连接较弱；只有口播描述结果不能充当该视觉结果。
保留 none/verified/uncertain、弱结果参与和原因果约束，不改 gap、relation 或资格状态算法。

使用阶段注册表中的一段共享说明，替换上面四处手写定义。
compact_eval 只同步当前执行指令，不重写历史实验材料；它不进入正式生产准入计分。
这是会影响模型输入的定义修正，必须独立提交和 refreeze，不能称为零行为变化的格式清理。
本步骤不以测试字符串通过宣称准确率提高。

### 2. 仅在资格入口设计一个候选

候选只附加到 Stage1-B/D 的 S4 result_presentation 判断，不改 Stage1-A、Stage2 或总结。
使用现有 signal_bindings.reason 和 evidence_ids，不加字段、调用层、检索或反思模型。

候选指令内容固定如下：

> 判 result_presentation=supported 前，reason 必须具体说明：现有哪条画面事实呈现了
> 什么产品相关结果，观众能从该结果理解哪项功能。操作已经结束、拿起/拧干对象等
> 时间顺序，不自行证明产品结果成立；功效口播及商品背景不能补出不存在的画面。
> 不以 fact_quality.proof 标签或 readiness 状态代替具体事实核对。
> 有真实但有限的结果仍可 supported，不要求所有商品都有 before/after、完整过程或强因果桥。
> 看到了操作但未呈现结果，记录该信号 missing；覆盖不足或事实冲突则 unknown。
> 阶段 absent/partial/present 继续由原合同、全部 signals 和覆盖状态决定，不能单凭此句直接改 NA。

这是既有结果参与边界的候选表达，不是增加“显著”“完全去除”等新门槛。
商品地基中模型推断的目标只作背景，不能升级成 SKU 功效事实或硬性“完全消失”要求。
资格 builder 保持不变，候选先隔离在既有诊断目录中，保留可调用的原 baseline。
共同的定义一致性修正须先提交及 refreeze，再同时用于两臂；不能把旧定义与新资格候选一起变动后称为单变量。

## 反例保护

| 场景 | 不应丢失的边界 |
|---|---|
| Fasclean：只看到搓洗、提起干净衣物 | 不自行补出污渍去除；S3 使用信息保留，不等于整条视频没价值 |
| 唇泥：直接看见成妆和显色 | 可以存在 S4 结果，不要求额外补一个传统 before/after |
| NIUMO：短暂接入后显示开始充电 | 可以是真实弱结果；不能一律改 absent 或固定判 medium |
| 只说洗净、快充等结果 | 口播不能充当视觉效果；不影响其可能承担 S1/S3/S6 的实际功能 |
| 覆盖不足、遮挡、矛盾 | 保留 unknown；不借此输出 none 或双方 NA |

NIUMO 的理由来自既有人工确认，见 `gap-boundary-consistency-20260929.md`；
其旧事实包不作为现行合同的原生验证输入，不能为凑控制样本降低兼容要求。

### 弱结果材料核准（2026-10-06，零调用）

NIUMO C1 **benchmark 的 B8 可保留为弱结果业务判例，但尚未准入本次现行合同模型对照**。
原子事实在 39.5–43.6 秒记录插入手机、屏幕 Charging 与电池状态；人工确认的是短暂、有限的
“开始充电”，不是快充、温度变化或多设备同时充电。不能因没有传统前后对照将其一律否认，
也不能因为口播提到快充，把普通 Charging 图标升级成快充证明。

核验文件与 SHA256：

- `runs/20260910-similar-format/niumo-c1-sg4/video_facts_benchmark.json`：`d3d5b403bc359d738c97ee51dcc01ef7a85f0416632ca524605b1efaaa7ce79f`
- 同目录 `analysis.json`：`f21457376b42b51b9e5bbd28f9d34483f633bb0db966756846c7170d2634e7c6`
- 同目录 `human-review.md`：`0774cce23898b49e47be00ee34b2f38b9d7cd60470ff8fb283cef54d583cfd26`

原事实为 v7；10 月 1 日另行资格请求针对 v8，不能冒充本轮 v10。
此前整对 NIUMO 的阻断包含 creator C6 的弯折/耐久解释问题，不能移植成 benchmark B8 没有充电画面。
本轮仅核准 B8 的上述有限用途，不采纳旧资格结论、不授予历史整包兼容例外。
原商品地基由模型推断选中“多口同时快充”，与 B8 可观察的普通充电不同；保留这项来源局限，
推断目标不能当作唯一硬门槛，也不能改写地基来凑一个看似完全匹配的控制。
因此四输入清单仍缺一个**现行可调用且完成来源准入**的弱结果输入；本次不启动 16 次实验，
不增发资格请求、不重跑视频。业务判例已核准，不等于实验输入已获准。

## 验证：最多一次有界开发对照

先离线验证四个实际 prompt 入口定义一致；无字段/Schema/非 S4 变化，
候选内容只抵达 S4 的 B/D，不泄漏到 A 或其他阶段。用项目既有测试，不另建框架。

原 Fasclean 双侧 + 唇泥双侧的四输入设计撤回：它没有真实弱结果控制，不能启动。
推荐仍保留四输入、两臂各重复两次：Fasclean r1 双侧、唇泥 r1 creator、一个已准入的真实弱结果角色。
弱结果优先核对既有 NIUMO C1 benchmark，但目前只有旧合同材料，未获本轮兼容准入。
不能把旧资格转换为原生 v10；不为凑控制重跑视频，输入未准入前实验保持阻断。
输入准入后必须先锁定文件路径、角色、SHA256、合同版本与预期判断，才可冻结调用清单。
重新构建现行 S4 资格请求，不能将人工 GT 或
旧 stage_evidence_checks 放进请求，不能改原始 proof 标签；两臂除候选指令外保持一致。
baseline/candidate 同期各重复两次，顺序 B/C/C/B；总上限 **16 次实际网络发送**，
包括技术重试。预算耗尽或不可恢复失败就停，不补调用、不拿历史响应凑配对。
没有新视频、OCR、ASR、Stage2、总结或 HTML 调用。

开发通过条件必须同时满足：

1. 候选对 Fasclean 双侧两次均未把操作结束/衣物状态作为 result_presentation supported；
   与已有人工 NA 对应的 absent 必须由原合同和完整覆盖正常闭合，不能脚本直接指定。
2. 唇泥 creator 两次均保留可见成妆结果的 supported/present，不新增错误降级。
   弱结果角色两次均保留 result_presentation=supported 且合法参与，不得变 absent/unknown。
   弱表达不等于 partial 资格：present/partial 是否合格由全部合同信号决定，不用 small 标签推算资格。
3. 指向有效证据 ID，版本、结构、完成状态通过现行校验；不以修 JSON 补语义或放行拒绝。
4. 相对同期 baseline 确有上述参与判断的修正，且无正向对照回归；
   如果 baseline 已全部正确，不能宣布候选提高准确率或默认替换。

每份输出先执行现有闭世界引用、资格及采集校验；无效引用算失败，不删引用后补过关。
候选只接受现有 signal_bindings.evidence_ids 引用：reason 中的自由文本时间不能替代合法 ID，
即使时间在视频范围内也不是结果证明。逐份人工阅读全部实际输出（最多 16 份），
由主 agent 核对引用对应的原始画面事实是否真的支持产品结果；拿不准的具体画面再升级给用户。
不让用户填写模型字段，不让新模型给本轮输出充当裁判。

两臂各固定 8 个输出机会，重复不算新样本。分别报告结构/引用失败数、
已解决资格覆盖率（present/partial/absent 且完整通过门禁）/8、unknown/conflict/失败数、
合法 absent 比例 /8，以及正向控制保留率 /4；这些分母不随弃答缩小。
本实验只调用单侧资格层，不生成 Stage2：不能把 absent 比例冒称最终 NA 比例。
Fasclean 只有双侧在同轮合法 absent 时才报告“满足双方 NA 的资格前提”，共两个配对机会。
更多 unknown 是暴露证据不足，不直接认作回归；但目标格变 unknown 不能替代本次要求的合法 absent。

这些是 4 个已见角色输入，不是 16 个独立样本。只作冒烟验证，不报告总体准确率提升，
也不直接启用第 2 步候选。未入模型 cohort 的未知覆盖边界以现有离线门禁测试保护，
明确不能据此宣称模型已通过该类场景验证。

失败即关闭这版候选，不接着改措辞再试，不增加调用预算。
代码修复与验证分开记录：实现、实验结果、启用分别注明，不把“已实现”写成“已有效”。

回退使用前一个冻结版本，不改历史产物、人工结论或成功标记。
