# Content Framework Engine Prompt Template

## 输入

- Product Fact Card
- Reference Video Card
- Operator Highlights
- Target Market: Thailand or Malaysia

## 任务

生成短视频内容框架，而不是完整视频脚本。

## 步骤

1. 定义任务边界：明确目标市场、销售平台、价格、目标人群、使用场景和内容目标；缺失信息列入假设或待核实，不得补造。
2. 做产品大判断：判断产品的决策动力、购买方式、信息方式、决策风险、核心驱动、结果出现时间和自用/送礼属性，先判断产品靠什么成交，再决定内容表达。
3. 提炼品的课题：必须是“场景痛点 + 根本需求”，不得拔高到产品事实无法支撑的抽象价值。
4. 识别消费机制：按“刺激/痛点 -> 状态变化或结果 -> 人的反应/利益 -> 可复制证明 -> 价值合理化 -> 行动”形成因果链；缺少证明或行动时，不能判定为完整带货框架。
5. 定义唯一品命题：明确核心人群、关键情境、产品独特作用、核心结果和购买成立条件，并压缩为能指导镜头取舍的一句话。
6. 提炼差异化卖点：每个候选卖点必须走“提出 -> 质疑 -> 本地需求证据 -> 保留/剔除/待验证”。卖点是否成立与是否适合做短视频主视觉必须分开判断。
7. 对成立或待验证的卖点做短视频呈现排序：
   - 第一排序是视觉证明能力：能否在短时间内通过状态变化、动作演示、前后对比或外观特写形成明显视觉信号。
   - 第二排序是功能决策价值：当多个卖点都能充分可视化时，优先解决核心使用问题、对购买决策影响更大的功能卖点。
   - 高视觉、高功能卖点标为“主视觉卖点”；其他可展示卖点标为“次视觉卖点”；难以直接拍出差异的参数、材质或认证卖点标为“口播辅助卖点”。口播辅助不等于不重要或卖点不成立。
   - 可以使用模型的品类常识判断视觉空间和功能优先级，但不得用模型常识补造产品事实；判断依据和不确定性必须显式输出。
8. 确定 1 到 3 个目标人群：按需求强度、产品匹配、场景可视化和成交证据排序，不用宽泛年龄或兴趣标签代替购买动机。
9. 推导本地化场景：只围绕主视觉和次视觉卖点设计证明动作；口播辅助卖点进入字幕或简短口播，不强行设计虚假的对比画面。先给时间、地点、角色、生活细节、触发动机，再组合成可拍摄场景。
10. 生成两条框架：人物生活线、卖点场景线。每条必须包含内容目标、目标人群、最强成交画面、证明计划、最大异议、价值合理化、情绪/交易 CTA 和测试变量。
11. 配置内容组合：区分拉停留、拉点击、拉转化、临门成交/控退款，不要求一条视频承担全部任务。
12. 自检：逻辑一致性、场景失真、文化宗教禁忌、主视觉卖点是否真的能被画面证明，以及结果是否存在可验证的测试指标。
