# ADR-008：原生视频只作为定向复核材料

**状态：Accepted**
**日期：2026-08-13**
**范围：Stage1-A/B/C/D、Stage2、Phase C**

## 决策

生产模型职责固定如下：

| 职责 | 模型 | 写入边界 |
|---|---|---|
| OCR、Stage1-A 视觉观察、Stage1-C 定向视频补观察、Phase C 视频回看、视频身份观察 | `qwen3-vl-plus` | A/C 只能写观察；C 不能写资格，Phase C 只能写受限 patch |
| Step-0、Stage1-B 首次资格、Stage1-D 定向重投影、比较资格、Stage2/Stage3、综合建议、翻译与世界知识判断 | `qwen3.7-plus` | B/D 只读 Canonical 观察，不能补写或改写原子事实 |
| 人工 judgment 备份 | `qwen3.6-plus` + `qwen3-vl-plus` | 仅显式替代 3.7 判断角色；视觉职责不变，不得自动 fallback |

旧 `--llm-model` 单模型入口只保留给历史严格回放，不是生产备份路径。

模型路由不新建账本、resolver、Phase C 或状态定义。`qwen3-vl-flash` 已退役，所有 provider 调用在共享边界拒绝该模型。

1. Stage1-A 的权威主输入固定为 canonical frames/时间线、窗口安全 ASR 和 OCR。provider 即使支持原生视频，首次事实抽取也不发送整支视频。
2. Stage1-C 在事实冻结前最多执行一次。它只接收目标阶段的原生视频窗口和同窗词级 Fun-ASR，只能追加候选观察，不能输出 `stage_evidence_checks`、删除或改写已有事实；没有词级时间戳时不得回退粗粒度 SRT 推断窗口口播。代码将候选 ID 映射进 Canonical Ledger 并记录映射，Stage1-D 再由判断模型只读 A/C 观察重投影目标资格。
3. Stage2 只读取冻结 facts，不接收视频或音频，也不能补写 Stage1 未采集的事实。
4. Phase C 在事实冻结后最多执行一次，并与现有 Phase C 预算和补丁合同共用同一条路径。它只能校验既有事实的资格或连续性，不能新增 `evidence_units` 或改写 severity。
5. 原生视频失败时保持 `unknown` 并写审计产物，不重复调用、不退回整片扫描、不伪造通过。
6. 历史 `s4_visual_verifier` 产物保持只读兼容，但生产主链不再调用其独立 provider；S3/S4 统一进入 Phase C。
7. 北京 MaaS 的 VL 路由只声明原生视频视觉能力，不声明原生音频理解能力。口播语义始终以 Fun-ASR 的窗口安全文本为准；视觉缺口和音频/转写缺口必须先按模态分流。

## 证据

2026-08-12 的同样本配对实验显示：

- 原生视频和 canonical-frame 路径的 Stage2 精确准确率均为 `10/33`；
- 差一档以内为 frame `22/33`、原生视频 `20/33`；
- 33 个格子中 9 个因输入模态变化而改变判断，但没有净准确率收益；
- 原生视频 Stage1 的 S6 代理覆盖率为 creator `16.7%`、benchmark `25%`，frame 路径均为 `100%`；
- 原生视频平均请求更慢、上传量和 prompt token 更高。

这组数据没有人工 `key_events`，不能证明真实召回率或精确率；因此它足以否决“原生视频替换主路径”，不足以 promotion 原生视频的语义收益。

审计产物位于 `runs/verification-native-video-20260812/report/`，`promotion_eligible=false`。

## 触发合同

Stage1-C 使用以下稳定 reason code：

- `stage_coverage_incomplete`
- `temporal_continuity_uncertain`
- `evidence_qualification_conflict`
- `s6_tail_unclosed`

Phase C 只接受独立结构信号。模型自报 `low_confidence_stages` 只能与上述结构信号关联，不能单独消费原生视频预算。

## 审计字段

每次原生视频调用至少记录：

- 所属阶段（Stage1-C、Stage1-D 或 Phase C）；
- 目标 role、stage 和实际时间窗；
- reason code；
- 请求字节、耗时、执行来源和 provider artifact；
- 有效补丁摘要与仍未闭合的阶段。

## 明确拒绝

- 用整支原生视频替换 Stage1-A；
- 每个 S1-S6 单独调用一次原生视频；
- Stage2 同时读取 facts 和整支视频；
- 新建平行于 Phase C 的第二套复核器、预算器或账本；
- 在 `qwen3.7-plus` 失败时静默切换 `qwen3.6-plus`，或回退到已退役的 VL Flash；
- 针对品类、商品或关键词写死触发规则。

## Promotion 门槛

本架构先以 shadow/audit 方式积累数据。只有人工 `key_events` 能证明定向原生视频对关键事实召回、资格准确率或最终判断带来可重复净收益，才允许扩大使用范围；否则保持当前定向复核定位。
