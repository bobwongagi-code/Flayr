## 执行顺序

同日后续重新冻结仅统一 `small` 的执行前提：有证据支持、可辨认但较小的差距，不以双方都执行为前提。
单侧有限执行可以是 small，不等于一律 small，也不按有无动作自动定档。该纠正与既有单侧比较许可对齐，
会改变模型所见文字；不修改 medium/large、none、NA、uncertain 或资格门槛，不改 GT、不重跑旧产物。
见 `gap-boundary-consistency-20260929.md`，准确率收益仍未验证。

以下为 2026-09-29 的历史冻结内容，其中 S2/S3 解释扩展已于 2026-09-30 撤出当前运行：S3 比较讲解与演示的整体有效增益，
不因“讲解相当”抹去演示收益，也不按动作自动升档；S2 不借后续演示、效果或参数数量加分。
Phase C 只补事实，不判执行分；证据按实际功能而非开头/结尾机械归属。
这会改变模型所见指令，不能称为纯格式修复或准确率已提高。档位定义、资格门槛、GT、
路由和预算不变，旧产物不迁移、不重跑，`promotion_eligible=false`。
此前无产品语音合同 v8 与 S4 四态约束修正继续保留；上文 v7 描述为历史修正记录。
完整范围、未解决语义问题与验证见 `stage-instruction-consistency-audit-20260929.md`。

1. 先盘点现有 GT 和身份兼容的历史 artifact，不调用模型。
   只有 `_SUCCESS.json` 可校验、模型路由一致、分析 schema 与管线版本一致，且代码身份属于冻结行为
   提交或当前已通过冻结校验的源码时，artifact 才可进入评分。身份缺失或不兼容的产物单列清单。
2. 旧 16 组通过 `legacy-gt-migration-inventory.json` 显式保留歧义。旧 `small` 不自动解释为

3. 先离线计算 Stage1 关键事实召回、资格保存、Stage2 使用、relation、gap、完成率和失败类型。
4. 盘点完成后，只有缺少必要且当前身份兼容 artifact 的样本允许定向调用。成功调用立即冻结，

5. 不达标时只选择贡献最大的一个根因，进入新的、版本化的单变量验证周期。

## 冻结门槛

- 至少 12 组可评分样本；
- 至少 12 个 relation 格；
- 至少 12 条人工关键事实；
- gap 与 relation 准确率均至少 80%；
- Stage1 关键事实召回率至少 90%；
- gap 预测覆盖率 100%；
- 两档错误、方向反转和 `NA`/可比较状态误判均为 0。

零严重错误是全自动生产晋级门槛，不是对永久能力边界的一次性判决。出现一个严重错误时，本轮不得
晋级，但必须先按冻结规则归因。不能在同一轮里删样本、改阈值或改 Prompt 后继续累计分数。

## 冻结期间允许修改的边界

| 问题 | 处理 |
|---|---|
| 网络或供应商瞬时故障 | 记录或技术重试，不修改语义合同 |
| request identity、字段丢失、代码崩溃等确定性工程 bug | 新 commit 修复，重走技术门禁，并开始新的语义周期 |
| Prompt、schema、资格定义、gap 标尺 | 当轮禁止修改，只登记为下一轮候选 |
| GT 或评分器错误 | 停止评分，版本化修正后复算现有输出，不自动重跑模型 |
| 因结果不好而修改样本、阈值或分母 | 禁止 |

- unresolved 格子从语义分母排除，同时在覆盖率报告中显式出现。

## S4 梯度 A/B 的现行解释

严格 A/B 确实完成了 8 次新调用，两臂协议哈希一致，4 个样本的最终 relation 和 gap 输出完全相同。
但实验之后 Frosty 从 `large` 修正为 `medium`，Niumo 和 Pet Chews 从 `none` 修正为 `NA`，因此旧
`2/4` 不能继续作为当前准确率。

可保留的结论只有：在这 4 个 seen 样本和当前传递方式下，人工复核梯度没有改变最终输出，因此
没有观察到局部输出收益。GT 修订使旧绝对准确率失效，但不改变“两臂逐格输出相同”这一观察。
