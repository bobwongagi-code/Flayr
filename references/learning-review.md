# 方向 A：学习交稿辅审执行入口

适用：团队提供爆款拆解教学、storyboard，查看交稿如何表达产品价值，并给下一条拍摄建议。明确必拍要求核对另走 [requirement-review.md](requirement-review.md)，不能把教学自动变成必拍清单。

## 先恢复业务依据，再写建议

1. **商品地基。** 复用现有资料中的产品特点、当地购买疑问、使用场景、消费者希望获得的结果、可观察信号和证明条件。厂家主张是参考，不是已验证功效或当地需求。没有依据的内容写未知；创意场景写提议。不要让用户重讲已经确认的产品和业务要求。
2. **整片购买理由。** 写出本条要让人相信什么、已有内容支撑了什么、最重要的缺口或待核点。吸引、产品引出、讲解/使用、结果、主动背书、购买引导是检查功能，不是互斥时间段、六项打勾表或固定顺序。先判断产品价值有没有讲成立，不能从最好截的图倒推首要建议。
3. **教学与实际表达。** 并列教学原话/时间及目的、爆款对应做法、交稿事实与时间。看观众实际获得什么产品理解，认可合理替代。教学不是内容判断的唯一边界：商品地基和已确认业务要求仍用于整片分析。未在教学中讲过的建议注明分析者提议，不伪装成教学要求；不推断作者是否看过教学。
4. **选择改法。** 先完成整条视频的内部复核，再按已核问题的重要性选择具体镜头、动作、情境、话术或剪辑方式。不预设只能一项或最多两项，也不为覆盖阶段凑意见；篇幅短不能成为漏掉重要问题的理由。相关建议可以相邻呈现，但实际使用与效果展示等独立信息问题必须各自说明，不合并后声称只有一个问题。“讲清楚”“加强表达”不是可执行建议；近景、背景、时长只是实现手段。
5. **人工交付。** 内部保留一句判断、时间/截图、待核项和理由；外发只用确认后的事实及具体拍法。作者稿按[沟通用词执行版](creator-communication.md)使用名字、“你的视频”及“同款参考视频”，建议用“可以……试试”；不显示档位、内部状态，不承诺改后销量。原声未核、本地语言未定等仍明确保留，不因机械检查通过而放行。这里更新人工辅审稿，不改旧自动报告生成器。

## 作者文字怎么检查

用词与交接命令执行[创作者沟通用词手册](creator-communication.md)，不逐项照搬原候选手册。另参考ClipMentor的[口播与字幕经验教训总结](../../ClipMentor/口播与字幕经验教训总结.md)，只提取适用于学习辅审的原则，以下内容在本文件直接执行，不依赖另一个仓库才能理解。

- **把动作和产品价值连起来。** 作者稿要让人明白这处拍法帮助观众理解什么购买问题。例如眼霜局部特写用于看眼周状态；不能只剩“拍近一点”，也不换成“高转化打法”等空词。解释表达作用不等于证明销量因果。
- **改顺口，保留必要条件。** 删重复、长修饰和审核术语，保留对象、部位、使用阶段、比较关系、实际记录时间等成立条件。02可以把“并置”改成“拼在一起”，不能因此删掉同光线、同角度及真实时间；两侧图不能缩写成未核准的“同一张脸的前后”。
- **建议口吻与明确判断并存。** ClipMentor解释参考做法，Flayr还要指出本条的具体问题及改法。可以说“可以……试试”，不必把判断写成训话；也不为亲切添加夸赞、俚语、虚构经历或收益承诺。风格偏好不能当事实纠错，已经自然准确的句子不强改。
- **文字、图片各承担明确的信息。** 正文说明为什么改、具体怎么拍；截图及图注指明实际位置与参考做法，内部记录保留来源、范围和未核项。省去正文重复时须确认信息确实由图或注释承载，不能笼统说“图里有”。限定条件只限制相关说法，不把整条建议写成免责说明，也不把未知从内部记录删掉。
- **看当前实际交付稿。** 改完逐项对照当前正文、截图和摘要，不能只看旧稿或模板。将来翻译时保留相同对象、条件和承诺强度；自然度、母语核准及可交付状态分别确认。只改中文不等于当地作者已能直接使用。

任务边界：作者回复的结尾是让作者知道下条如何着手拍，建议里的消费者小黄车话术只是拟拍内容。不要混成催作者购买或重复邀请已成立的合作。ClipMentor的观察式第三人称、辅助短标四词限制、同步字幕同文和配音时间线要求，不套到当前图文建议；以后确实制作音视频时再按对应流程处理。

## 缺失、有限与未知必须分开

- “没有展示”：连续核看完整相关范围及必要音轨/字幕，或有同一视频、范围、目标的明确人工核实；记录依据。1fps 图板和完整转写不能单独证明视觉缺失。
- “未找到”：抽样或关键范围未核完；仍可说明已有材料的支撑范围，但不把候选缺口发成确定整改。
- “已有但有限”：保留真实贡献，不因短暂或不充分写成没有；普通对象状态、涂抹动作也不自动证明产品功效。
- 真实使用后可辨的效果变化应认可，包括当次可见结果和跨日连续记录。区分动作与效果，是为了看清结果，不是把个人效果展示提高到临床因果证明门槛。结合商品和实际记录判断，不统一要求或排斥七天、同天、跨天；开不开美颜也不作为默认整改项。内部核查不例行转成作者正文的警告。
- “下一条可以加”不能绕过是否已拍过的核对。表达建议不批准具体功效、记录时长或合规口径。

## 材料检查，不是自动判断

沿用现有 `cases.json`，不新建评分表。商品级增加 `product_context.review_foundation`，只作已有地基的人工辅审投影，不冒充生产 `product_profile`：

- 五项为 `core_selling_points`、`usage_context`、`consumer_outcome`、`observable_signal`、`proof_condition`。
- 每项保存 `text`、`basis`、`source`。`basis` 只能为 `source_claim`（来源主张）、`user_confirmed`（用户确认）、`analysis_proposal`（分析提议）或 `unknown`。未知项写清缺什么及已查范围，不补造结论。
- 每条沿用 `product_question`、`reference_logic`、`teaching_points`、带 `kind/evidence/text` 的 `facts`，以及 `whole_video` 三项。没有首要缺口时直接写依据，不硬造一个。

从仓库根运行：

```bash
python3 scripts/validate_learning_review.py /absolute/path/to/cases.json
```

交接具体作者稿时，追加 `--author-copy /absolute/path/to/author-draft.md`，多份稿件重复该选项。它只查指定作者正文的有限用词问题，规则与内部区格式见[用词手册](creator-communication.md)；不可用材料检查单独通过来代替作者稿检查。

检查会拒绝漏掉商品依据、整片论证、教学联系或证据出处字段的材料。CLI 还会读取 `teaching_reference` 指向的本地 UTF-8 文件，拒绝不存在、空白或无法读取的文件；相对路径以 `cases.json` 所在目录为基准，不下载 URL。纯函数 `validate(data)` 只查结构，交接应运行 CLI。

**仍不核验**教学编号是否存在、事实引用是否指向真实条目、截图语义、来源真假、论证或优先级。输出明确保留这层限制，不能称“证据链验证通过”。失败时补真实材料或记录未知，不填空话过关。通过不改变审核状态、不自动生成建议、不调用生产分析链。

人工终审再问三件事：建议是否解决本品的主要购买疑问？是否误删已有贡献或把未知写成缺失？能否直接照着拍且没有许诺结果？只有图更漂亮、字段更完整不能证明有价值。

## 交稿前的执行复核

执行者完成以下复核，写入本批现有审核记录；不新增用户填表、模型调用或评分。字段检查通过后仍须完成。

1. **主问题与优先理由。** 先用 `whole_video` 说明本品购买疑问、已有支撑、主要断点，再写回复。内部留一句为什么优先处理它，而不是容易举证的局部问题。主要问题未知时保留待核，不能用安全的小建议替换。

   内部先过整条的吸引、产品引出、功能/使用、结果、信任及购买引导，记录已有贡献、已确认问题、可选改善和待核项。检查覆盖全部职责，不要求全部都有缺陷或都发给作者。图文与用词检查完成不等于整片内容复核完成；原声没听或只有抽样也应如实保留，不虚称完整视听内审。

   对每项已有表达继续核对：是否回应本品本条的购买问题、是否让观众看清具体信息、是否与前后内容接得上。“有钩子/有介绍/有CTA”只回答存在性，不能直接写成表达充分或无需改善。再看整条是否围绕同一购买问题推进，重复介绍、指示或收尾是否挤掉使用与结果的必要内容；时长只用于定位内容分配，不按秒数或镜头数量判质量。该检查同时允许保留已有表达并改善其质量，不把改善写成原本没有。
2. **反证检查。** 检查视频是否已经做过建议内容、是否有等效表达、事实是否来自同一视频及适当范围、参考是否真展示了所述做法。记录检查范围及来源；缺失结论遵循上文标准，截图存在不等于支持结论。

   肯定“使用表达成立”前，在现有事实与审核记录中明确三件事：本品本条诉求要展示的对象/部位是什么（注明商品或教学依据）；产品实际接触哪里、动作沿哪里展开（看相邻画面，不用单帧接触代替过程）；这个过程是否把目标用途讲清。使用存在、目标对应、过程可辨分别判断，不以“有动作”替代后两项。若主动作偏离目标，保留已经发生的使用贡献，同时指出偏差；看不清就保留待核，不自动肯定。参考片也按相同问题检查，不因为是参考就默认正确。这是内容表达核对，不推导医学禁用部位，也不设动作占比阈值。
3. **句子与交付证据绑定。** 每项改进连接具体问题、交稿证据、参考做法或明确标注的分析者提议、可执行拍法。比较句两侧都有依据；教学时间不得冒充原爆款时间。关键配图未附齐时保持待补材料，不称交付完成。文字修订按上文“作者文字怎么检查”核信息是否丢失，不凭更短、更亲切就判更好。
4. **已纠正案例检查。** 本批01不得退回只改开头；02保留实际使用，处理需求承接与不清晰的结果展示，不把指两侧写成清晰效果；03保留手背质地贡献但不替代眼周使用；05不得再把指眼袋写成实际使用；04已有施用后呈现，不能套用其他视频的无结果结论。这些已曝光案例只防止旧错误重现，不是独立验证集或全品类规则。

   04后续用户纠正：确有眼部涂抹，但大量动作着重脸颊，未突出本条眼周纹路的目标区域。使用存在不等于使用表达已到位，应与结果对照不清楚分别给建议；不得再写成“使用直接保留、只改结果”。不将本例扩成“脸颊永远不是有效用途”。

   05后续纠正：保留已有眼周痛点，同时检查多部位铺陈是否分散重点、产品介绍和收尾是否重复；使用与结果建议之外，仍需判断整体内容分配。不能因已选定两个补拍点便跳过结构，也不把本例推广成所有视频只能讲一个部位。

记录只需主问题及优先理由、反证检查及来源、交付证据是否齐备、具体待核项。执行者自查不等于独立审核，程序不能凭文本非空证明抓对了重点；最终采用仍由业务确认。用户不用重填商品依据或检查表。

送审前对照当前实际作者稿再反查：重要的独立缺口是否均已回应；暂不提的项目是否有具体取舍理由；照着每项建议做，能否补上它对应的信息。没有完成这轮内容复核，不能将稿件标成“已内审”或以脚本PASS代替交接条件；材料确实不足时，只提出相关事实问题。此条是执行者流程责任，当前脚本没有自动核验语义内审的能力。

出现已确认事实被覆盖、已做内容被写成缺失、局部打磨挤掉主要问题、图文不符时，退回受影响草稿修正，不扩样本或靠改语气放行。记录由执行者先查出还是用户指出。是否有效看后续首次草稿的这类纠正量；本批按反馈改过的结果不能证明首次判断能力或省时。

## PAPA FEEL 当前应用

用户在 2026-10-16 已明确本批要求实际使用与效果 before/after，不再等待“是否要使用/对照”的确认。这是本批业务要求，不是全品类标尺；不等于必须即时见效、跨日记录、暂停拍摄，也不代表每条缺失。

01 缺失由用户确认；02 已有使用和两侧观察；03 用户已确认只有手背试质地，后续指部位但未涂产品，没有本批要求的眼周使用和效果对照；04 已有施用后眼周呈现，不能预设无结果；05 用户已确认全片未实际使用，撤回此前“已有用法动作”的肯定判断。05独立结果素材是否另有仍未知，不从使用缺失推出结果缺失；已确认的使用缺口足以支持具体改法，不再等待无关未知。五条不能统一改成“补前后记录”。

02最新人工反馈补充：使用详细、位置正确，但缺少需求钩子及承接，指两侧不构成清晰的前后/两侧结果展示。上文“两侧观察”只指表达意图，不是结果已充分展示。01用户已表示反馈完成，不重复开启其事实审核。

02后续交付收窄：用户重新要求核听开头，旧人工来源保留，原声未核时不把开头判断放入当前作者稿。当前v3只优化已有两侧展示的近景、实际侧别和观察位置，不新增前后记录任务或CTA；这是本次建议数量的取舍，不是否定结果展示。真实连续使用、可辨变化的跨日记录可以作为效果依据，按记录认可其信息，不以临床因果证明要求否定个人before/after。具体天数及变化从已有记录核实，不预先替产品设定。

01–05本轮业务review已完成，五条保留为开发参照，不再重复打磨或重开确认。下一笔自然业务到来后，首次使用当前方法，沿用已有备注记录首次稿、实质纠正和实际审核用时；不另加用户表格。当前等待业务，不扩样本、不新增模型调用。中文review完成、当地语言定稿、发送和省时验证分别记录，不能互相替代。现状读[执行方案](papafeel-learning-review-plan-20261016.md)及本批 `product-review/README.md`。

更新确认状态时，同步 `cases.json`、当前审核简表、完整分析与对应回复顶部的内部状态说明；历史记录保留但注明已被取代。业务范围已确认、具体事实待核、建议未放行是不同状态，不能继续统写为“等口径”。`runs/` 是本机试点材料，不随仓库自动分发；本入口和检查代码留在仓库中，父工作区路由只是本机辅助，不作为唯一入口。
