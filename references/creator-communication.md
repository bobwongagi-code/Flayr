# Rootify创作者沟通与内容诊断用词手册：Flayr执行版

适用：Flayr的A、B、C中任何最终给创作者阅读、观看或收听的产物，包括反馈、报告页、参考卡、脚本、聊天话术及教学交接稿。内部商务分析、GT、原片台词和来源标识保留原貌。本版整理2026-10-16用户提供的手册及后续纠正，不作为其他仓库的默认规范。

## 写作原则

像一起做内容的伙伴，说具体、能照着拍的话。先判断商品购买理由与整条视频的问题，再写建议；亲近的口吻不替代判断，也不增加销售保证。

认可有依据的具体贡献，不强制先夸、不虚构亮点。先内部复核整条，再决定作者需要收到哪些问题及改法，数量由内容决定。简洁靠去重、排序和具体表达实现，不靠把不同问题硬合成一点或预设最多一两项。不靠“先给甜枣”掩盖问题，不把每次回复写成同一套三段式。

## ABC共用的轻量交付审核

审核对象由最终收件人决定，不由文件在哪个方向产生决定。内部资料不一律改成作者口吻；从内部资料生成作者版时必须审核实际作者版。检查和人工确认合并到原有内容定稿环节，由同一位内容负责人完成，无需新增审核岗位、队列或逐条审批。

| 方向 | 需要审核的作者产物 | 本方向额外核对 |
| --- | --- | --- |
| A | 学习辅审建议、交稿或返稿反馈、拍摄小抄 | 意见是否对应本条视频或已确认要求；不把教学参考自动变成必拍要求；事实、截图、具体改法是否相符 |
| B | 橱窗报告拍摄页、单独导出的建议、商务拟转发的相关话术 | 是否对应本次作者、商品和安排；未核本人视频时不编个人诊断；不扩大合作条件或承诺收益 |
| C | 对外参考卡、示范脚本、给作者看的借鉴说明；送往ClipMentor后形成的教学产物 | 内部标签是否漏出、参考在新商品下是否适用、借鉴目的及条件是否保留；源片认可不等于新讲解已审核 |

一次定稿同时检查三件事：读起来是否像面向这位作者说话；事实和图文是否支持建议；对方能否知道具体怎么拍。核对当前主要购买问题有没有在改顺口时退成次要信息，例如眼霜的眼周困扰与结果依据不能只剩质地和肤感。自动扫描处理有限的显式问题，语气、合理性和优先级由人确认。已经准确自然的句子不为统一口号而返工。

在已有任务备注中记一行即可：`最终文件/版本；审核人及日期；可发/待修改/待核事实；需改句子（有才记）`。“可发”只能由业务定稿人确认；自动检查通过不能填写这一结论。导出或可发均不代表已发送，不自动联系作者。

审核绑定当前版本。只改措辞时核对改句及相邻上下文和相关图注，重跑本地扫描；换商品、作者、用途、语言、关键证据或主要建议时，重查受影响的事实和适配性。同一用途下未变更且已核的来源材料直接复用，不重跑模型或要求用户重填GT。没有核过的内容不因复用而变成已核。

图文稿检查实际可见文字、图注和截图；音视频稿先查当前口播/字幕文字，再由制作环节核实际声音、画面与字幕。无实际音视频时只记文字检查，不能称成片通过。其他仓库负责成片验收时，交接已核范围及剩余责任，不让Flayr替下游宣告通过。

## 用词和拍法

| 场景 | 执行方式 | 避免 |
| --- | --- | --- |
| 称呼作者 | 名字、“你的视频”，行动句优先“可以……试试”；无需每句叫“你”或“咱们” | 对作者说“达人”“尾部”“小白”，强行使用“大神”“老大哥”等称呼 |
| 说明参照片 | 默认“同款参考视频”，并给对应画面和来源时间 | 将内部“标杆”换成未经核实的“跑得最快”“出单最多”；有业绩来源也不能由此认定拍法导致出单 |
| 解释问题 | “开头直接展示产品，还没让大家看明白为什么需要它” | 未经观众数据核实就说“产品出早了，把买家吓跑了” |
| 解释比较 | “隔着屏幕不容易看清，可以把前后画面拼在一起” | 将表达不清写成造假，或将未核图片称为同一人的真实前后效果 |
| 给拍法 | 具体说明拍哪个部位、手怎么放、镜头怎样拍、可用什么话术 | 只有“加强表达”“高转化打法”，或只描述动作而没有产品信息目的 |
| 质地与用法 | “挤一点推开，拍清质地，聊真实使用感”；按本品用途选择部位 | 自动添加“有多润、吸得多快”，或把手背试质地当成本品实际用法 |
| 优惠和收尾 | 只使用确认过的商品组合、价格、购买路径；作者行动和视频内消费者CTA分清 | 未核赠品、“只要两位数”、免费寄样、丰厚佣金、合作服务或收益承诺 |

不用固定词库机械替换。中文先准确自然，将来翻译再结合对象与本地反馈选择马来语；普通词不整批禁用，俚语及中英混用不自动优于普通表达。用户手册中的马来语列为候选，不能直接标为已验证的“高频爆单词”。

## 边界如何表达

作者正文直接讲具体怎么拍。证据不足、功效不能据此认定等审核判断在内部处理，不额外塞进“别说成已经改善”“关掉美颜”等例行提醒，也不靠否定句反复表态谨慎。开不开美颜及个人拍摄风格由作者选择，不作为默认问题项或整改要求；内容诊断看产品信息、实际使用及结果是否表达清楚。需要的拍摄条件直接写进动作，例如“两眼同框、光线和镜头距离保持一致”。内部另存来源、未知与核准状态；改顺口仍须保留部位、比较对象和相关时间等真正影响拍法的信息。

不写“真实变化最能出单”“出单率大概率翻倍”等无依据的因果或预测。可以解释“帮助观众看清、理解或比较什么”。“因人而异”不能补足一项原本没有依据的宣称；精确功效、时间、数量、权益仍按来源核实。

真实连续使用记录可以作为带货视频的效果依据。比如同一人实际使用后的第1天、第4天、第7天，画面清楚呈现颜色、纹路等变化，就认可这组before/after的信息价值；不拿临床或实验室因果证明门槛否定个人效果展示。评价记录是否真实、变化是否可辨、话术是否与记录相符，不按同天/跨天一刀切。示例天数不变成产品见效承诺，个人记录不自动扩大为所有人的固定结果。这些是内部判断原则，不例行写成作者正文的免责声明。

### 已纠正的执行错误

以下用于交稿前人工复核，不能靠简单关键词推断语义，也不要求用户另填表。

| 曾出现的错误 | 当前执行方式 |
| --- | --- |
| 把“关掉美颜”“不说成改善”塞进建议末尾，逐句自我防御 | 作者正文只留具体拍法；拍摄风格不列整改，证据判断内部处理 |
| 用“跨天也不证明功效”笼统否定连续使用记录 | 真实使用后清楚呈现变白、变淡等变化的记录，认可为个人效果展示依据；实际变化具体说 |
| 将同天一概归为只能看使用，或将跨天设为唯一合格条件 | 结合商品及画面；当次即可看清的结果也认可，长期变化可用多日期记录，不设统一天数门槛 |
| 因为曾误判效果，后来一律不敢判断有结果 | 区分实际使用、可见状态与可辨变化，已有真实结果保留其价值，疑点具体核实 |
| 为提醒真实记录而给所有作者新增跨天拍摄任务 | 先看本条已有哪些材料，再选择最有价值的改法；02目前优化两侧镜头，不自动替换成七天记录 |

交接检查仍为同一轮：自动查有限显式用词，执行者对照上述例子检查是否重犯，原内容定稿人确认采用。不新增调用、审批层或评分；自动扫描不证明个人记录真实或功效成立。

## 每次交接怎么执行

1. A学习辅审按[学习辅审入口](learning-review.md)完成商品与整片判断、反证检查、文字与截图绑定；B、C按上表检查本方向的事实、用途和适配。
2. 修订当前实际作者稿，保持作者正文和内部审核备注分开。图文稿的内部区统一用独立标题 `## 内部审核备注，不随作者正文发送`，交付时只取该标题之前的正文。
3. 对本次要交接的稿件运行离线检查，例如：

```bash
python3 scripts/validate_learning_review.py \
  runs/diagnostics/papafeel-learning-review-20261016/product-review/cases.json \
  --author-copy runs/diagnostics/papafeel-learning-review-20261016/product-review/author-replies/02.md
```

B、C或其他只有作者稿的任务可直接运行，不需伪造教学材料或cases.json：

```bash
python3 scripts/validate_learning_review.py --author-copy /absolute/path/to/author-copy.md
```

`--author-copy`可重复指定，一次查本次多个稿件。检查只读，不自动替词、不删除句子、不发送。它目前接收UTF-8纯文本或Markdown，扫描正文与图注，跳过Markdown链接目标及上述明确划定的内部区；不把整个混合原片转写当作者稿传入。它不解析HTML、PDF或视频；这些产物的可见文字及最终呈现须在现有交付环节核对，不能用一份旧Markdown冒充最终文件检查。

命中返回非零并给出行号，由执行者修订或核对，不能悄悄忽略后称通过。可检查的范围是内部称谓、部分明确收益预测和本次手册中的具体风险表达；并非完整的语义审核。没有命中仍须人工确认事实、优先级、拍法条件、自然度及最终采用。检查不证明销量、母语自然度或交付审批通过。
